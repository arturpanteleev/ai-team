# Dependency kill-watch (EXP-1)

Стратегия Track V (verification-инструмент) висит на одной ставке: собственный
контур доверия всё ещё даёт то, что форж/харнесы не делают сами. Трекер ниже
называет сценарии, которые это ставку убивают, и как заметить их рано.

Источник правил: `FEATURES.cloud.md`, §«Чего нет ни в codex, ни в ревизии 2».

## Сценарии, сигналы, действия

| Сценарий (kill) | Сигнал раннего обнаружения | Действие |
|---|---|---|
| GitHub Agent HQ эмитит собственную квитанцию с провенансом к agentic review | release notes; появление attestation в PR-интерфейсе | Уходить в то, что платформа не сделает: спека как контракт, containment-receipt, независимость от форжа (GitLab / локально) |
| Харнесы эмитят собственный attestation (Claude Code / Codex уже эмитят OTel) | появление in-toto/DSSE в выводе харнеса | Становиться агрегатором и верификатором чужих attestation, а не их источником |
| «Верификация — не боль»: люди просто читают diff | ≥3 интервью подряд с «нам это не нужно»; 0 внешних повторных запусков за 8 недель | Track V мёртв; возврат к Track P как личному инструменту (см. FEATURES.cloud.md §8) |
| Bundle никто не открывает, потому что он непонятен | человек не может пересказать, что доказано | Проблема истории, а не кода — переписывать вывод `verify`, не добавлять оси evidence |

## Правило пивота (Stop)

Shift на Track P как основной инструмент, когда выполнено **одно из**:

- три подряд интервью дали «нам это не нужно»; или
- ноль внешних повторных запусков за 8 недель.

## Где наблюдать

- GitHub: release notes, changelog agentic review / pull-request UI (появление
  attestation-бейджей), GitHub Copilot attestation-записи.
- Claude Code / Codex: вывод `--json` / `--output-format json`, OTel-экспорт,
  появление DSSE / in-toto / SLSF-полей.
- Собственные запуски: счётчик внешних повторных `gate`/`verify` за 8 недель.

## Импортированные внешние attestation

Первые два сценария означают смещение ценности от «мы выпускаем доказательство»
к «мы проверяем чужие доказательства и связываем их со спецификацией». В схему
attestation v1 заранее заложить поле для импортированных внешних attestation —
иначе схему придётся ломать через полгода.
