# Бэклог спринта качества (2026-09-24)

Новых фич нет. Только дефекты, стабильность и проверяемость.

## Как собирали

Пять независимых исследований, каждое обязано было приносить свидетельство —
`файл:строка` либо команду с реальным выводом:

| Исследование | Метод | Находок |
|---|---|---|
| Зашитые константы и лимиты | инвентарь + probe-тесты на фактическое значение | 14 |
| Утечки и параллелизм | счётчики горутин, воспроизведение на живом сервере | 12 |
| Нестабильные тесты | повторные прогоны, `-shuffle`, нагрузка, чужое окружение | 15 |
| Мутационное тестирование | 42 мутации в production-коде, 38 валидных | 17 выживших |
| Проверка гарантий исполнением | попытка сломать каждую заявленную гарантию | 9 |

Плюс 13 задач, открытых по итогам прошлого спринта.

**Итого 80 находок**, из них 2 уровня P0.

## Два факта, определяющих приоритеты

**Первый.** Все 17 выживших мутаций применили одновременно и прогнали весь
набор целиком — `pkg/pipeline`, `e2etest`, `cmd`, всё. Полностью зелёный. Это
не «пакетные тесты пропустили, интеграционные поймали»: в репозитории нет
ничего, что ловит хоть одну из них.

**Второй.** `go test -race -count=3 ./...` зелёный на 47 пакетах. Существующий
набор не затрагивает ни один дефект из разделов про утечки и параллелизм.

Отсюда следует приоритизация: сначала дыры в контуре, затем тесты, которые
обязаны были их поймать, и только потом остальное.

# P0 — ломает основное обещание продукта

## QS-01. LLM-этап сам себе выписывает delivery-approval

**Исполнено.** Этап `verifier` — обычный LLM-этап — отцепил фоновый процесс,
дождался появления `state/approvals/<run>/<id>.json` с `trigger: delivery_plan`
и переписал его:

```
trigger= delivery_plan status= resolved resolved_action= approve
decisions= [{"actor_id": "the-llm", "actor_role": "release_manager",
             "action": "approve", "subject_hash": "99eb6df…"}]
```

Затем `ai-team run --resume <run>` **без `--approve-plan`, без
`ai-team decision`, без TTY**:

```
resume exit=0
✓ delivery по run …: commit=e9519d9ce48d50f4a670fedbf1fd86b4934af971
                     pr=https://example.test/pr/e2e
```

**Причина.** Записи approval — обычный JSON без MAC и подписи, вне
hash-chain (`pkg/approval/store.go` целиком). Агент не ограничен корнем
worktree (`pkg/pipeline/workflow.go:33-35`).

**Последствие.** Центральное обещание продукта — «commit/push/PR выполняет
только контроллер после approval точного SHA-256» — обходится тем самым LLM,
от которого оно защищает.

**Критерий приёмки.** Запись approval подписана ключом контроллера либо
включена в hash-chain; решение, изменённое на диске, отвергается при resume.
Тест воспроизводит сценарий выше и требует отказа.

**Оценка.** M за криптографическую привязку. L, если делать настоящий sandbox.

## QS-02. Неаутентифицированный HTTP-вызов объявляет свою роль и утверждает план

**Исполнено** на дефолтном `ai-team web`:

```
GET  /api/auth/config → {"authentication_required":false}
GET  /api/session     → {"csrf_token":"…"}              (без Bearer)
POST /api/runs/<run>/approvals/<id>/decisions
     {"action":"approve","subject_hash":"…",
      "actor_id":"anon","actor_role":"release_manager"}
→ HTTP 200, status=resolved
→ ai-team run --resume → коммит в origin
```

**Причина.** `pkg/web/commands.go:222-244` — `actorID` и `ActorRole` берутся из
тела запроса; проверка роли выполняется только при `s.authenticator != nil`, а
в локальном режиме authenticator выключен.

**Последствие.** README описывает web UI как равноправный путь записи
delivery-решения, ARCHITECTURE обещает роль `release_manager`. Роль — строка,
которую пишет вызывающий.

**Критерий приёмки.** При `authenticator == nil` write-эндпоинты либо
запрещены, либо требуют локального токена. Fail-closed по умолчанию.

**Оценка.** S–M.

# P1 — дыры в контуре безопасности

## QS-03. Mutation guard и workspace digest слепы к целым классам каталогов

Ignore-набор (`pkg/checks/checks.go:589-607`) используется и для обхода дерева,
и для атрибуции мутаций. Поэтому `mutation: none` не означает read-only.

**Доказательство А.** `reviewer` с `mutation: none` записал `vendor/evil/evil.go`,
`node_modules/evil/index.js`, `dist/app.js`, `.ai-team/reviewer-was-here.txt`.
Манифест попытки: `reviewer | mutations= None | changes= 0`. Run дошёл до
delivery-approval.

**Доказательство Б, с последствием.** `verifier` (`mutation: none`) после
успешной required-проверки поменял её вход `dist/flag` с `good` на `bad`:

```
ai-team [tester]   ✓ PASS
ai-team [verifier] ✓ APPROVED
✗ Пайплайн остановлен: требуется решение человека   ← план предъявлен человеку
--- go test ./... на том же candidate:
--- FAIL: TestFlag   flag_test.go:15: dist/flag says bad
```

`verified_workspace_digest` не покрывает входы, которые проверки читают.

**Критерий приёмки.** Разделить ignore-набор на «для скорости обхода» и «для
identity/attribution». Для guard не игнорировать ничего, кроме `.git` и
`.ai-team`. Тест воспроизводит доказательство Б.

**Оценка.** M.

## QS-04. Агент пишет вне worktree; подсаженный pre-push hook исполняется контроллером

**Исполнено.** `coder` установил `.git/hooks/pre-push`; после одобрения плана
человеком контроллер выполнил push:

```
PRE-PUSH HOOK EXECUTED BY THE CONTROLLER DELIVERY STEP
mutations recorded for coder: ['e2e_implementation.go']   ← hook не зафиксирован
```

На `git commit` (`pkg/delivery/executor.go:379`) стоит
`-c core.hooksPath=/dev/null`, на `git push` (`:409`) — нет.

Отдельно: `echo … > ../coder-escaped-worktree.txt` создал файл вне worktree
без единого замечания.

**Критерий приёмки.** `core.hooksPath=/dev/null` во всех git-вызовах executor'а.
Тест с подсаженным hook'ом требует, чтобы он не исполнился.

**Оценка.** S для hooks. L для настоящего confinement.

## QS-05. `ai-team verify` печатает «Run OK» для подделанной evidence

Whitelist проверки (`pkg/export/export.go:411-441`) покрывает `events.jsonl`,
`anchor.json`, `attempts/*/manifest.json`, `config.json`, `workflow.json`,
`attestation.json`. `run.json` в списке есть, но **без digest**.

Не детектируется — все дают `✓ Run OK`:

- содержимое `run.json`: feature, target_dir, `controller.executable_sha256`,
  `controller.go_version`, все `provenance[].digest` обнулены;
- архивный артефакт `attempts/*-reviewer/artifacts/f1/review.md` переписан с
  `APPROVED` на `REJECTED` и другой длины — **при том что манифест хранит для
  него `sha256` и `size`**;
- удаление всего каталога `attempts/<id>/artifacts/`;
- `logs/*.log`, `candidate.json`, `usage.json`, `reports/*.html`.

Сообщение при этом утверждает: «anchor OK — event chain, manifests digest,
attempt manifests и attestation v1 согласованы».

**Критерий приёмки.** Пройти `outputs[].evidence_path` каждого манифеста и
сверить digest и size. Включить `run.json` в anchor. Тест на каждый из
перечисленных случаев.

**Оценка.** M.

## QS-06. Доставка не ограничена по времени и не прерывается сигналом

`pkg/pipeline/delivery_deferred.go:39` и `:227` используют
`context.Background()`. Дальше — `git commit`, `git push`, `gh pr view/create`:
три сетевых вызова без таймаута и без `GIT_TERMINAL_PROMPT=0`.

**Исполнено** с `gh`, зависающим на `pr create`:

```
B3 CONFIRMED: controller STILL RUNNING 15s after SIGINT
B3 CONFIRMED: controller survives SIGINT x2 + SIGTERM; only SIGKILL remains
B3 delivery subprocesses still alive after SIGKILL of the controller group: [74593]
```

Второй дефект в том же пути: `process.Run` переносит ребёнка в собственную
группу процессов, поэтому `kill -9 -<pgid>` группы контроллера его не достаёт.

Контраст: preflight ограничивает **те же бинарники** настраиваемыми 60 с.
Замер до реального remote — 2.90 с.

**Критерий приёмки.** Отменяемый контекст с щедрым дедлайном, отвязанный от
контекста run'а, но не от сигналов. Тест с зависающим `gh` требует прерывания.

**Оценка.** M. Вторая половина — это #116, оценка L.

## QS-07. Один зависший клиент дашборда навсегда вешает весь поток событий

`pkg/web/websocket.go:104` — `Hub.Run` проигрывает историю новому клиенту
синхронно и **блокирующей** отправкой в канал на 256 слотов.

**Воспроизведено** на настоящем сервере с настоящим клиентом (3000 событий,
клиент завершает рукопожатие и не читает):

```
goroutine 83 [chan send]:  web.(*Hub).Run(...)   pkg/web/websocket.go:104
goroutine 53 [chan send]:  web.ServeWs(...)      pkg/web/websocket.go:171
```

Хаб — единственный цикл обработки событий. Дашборд мёртв для всех до
перезапуска процесса; каждое следующее подключение навсегда подвешивает ещё
одну горутину.

**Критерий приёмки.** Проигрывание истории вне цикла хаба либо неблокирующая
отправка с отключением при переполнении — как уже сделано в ветке broadcast.

**Оценка.** M.

## QS-08. Сканер секретов: регистр, размер, глубина — три fail-open в fail-closed контуре

Три независимых дефекта в одном защитном механизме, блокирующем экспорт.

**Регистр** (`pkg/redact/scanner.go:141`, подтверждает #150 независимо):

```
Scan("password=Aa1bB2cC3dD4eE5fF6gG7")  → 1 finding
Scan("PASSWORD=Aa1bB2cC3dD4eE5fF6gG7")  → 0
Scan("API_KEY=…")  → 0     Scan("SECRET = …") → 0     Scan("Token: …") → 0
```

**Размер** (`:373`): JSON больше 4 МиБ не сканируется вовсе.
`small JSON (39 B) findings=1` против `big JSON (4194353 B) findings=0` — тот же
секрет. Текстовые правила не компенсируют: регулярка якорена на начало строки и
не матчит вложенное поле однострочного документа.

**Глубина** (`:317-319`): при вложенности глубже 16 сканер **бросает весь
документ**, а не пропускает поддерево. Секрет, стоящий после глубокого объекта
на верхнем уровне, не находится:

```
depth= 5 findings=1   depth=15 findings=1   depth=16 findings=0   depth=20 findings=0
```

**Критерий приёмки.** `(?i)` на альтернацию ключей; потоковый разбор или
пропуск поддерева вместо отказа; **запись в отчёт о том, что не просканировано**.
Позитивные тесты на верхний регистр, на большой документ и на глубину.

**Оценка.** S за регистр, M за остальное.

## QS-09. Run без секции `budget` не ограничен по времени (#143)

`pkg/config/config.go:89-98` возвращает `time.Duration(0)`;
`pkg/pipeline/pipeline.go:664` вооружает таймер только при значении больше нуля.
Константа `DefaultBudgetMaxWallTime = "24h"` нигде не парсится в длительность.

**Новое сверх #143:** `ai-team init` никогда не пишет секцию `budget`, и сама
секция не описана в README вовсе. Единственный рабочий способ ограничить run —
недокументированный ключ.

Сопутствующее (`pkg/config/config.go:568-575`): `stage_timeout` не имеет
дефолта на уровне кода. Конфиг, написанный руками, идёт без таймаута стадии
**и** без бюджета run'а.

**Оценка.** S.

## QS-14. Остальные 13 выживших мутаций

Каждая — отдельный тест, все по S:

- `pkg/delivery/executor.go:570` — проверка committed-байтов структурно
  недостижима в тестах: staged-проверка всегда срабатывает раньше;
- `pkg/delivery/plan.go:148` — evidence предусловий не валидируется
  структурно: план может нести пустую карту и быть одобренным;
- `pkg/approval/store.go:388-397` — `sameRequest` можно сделать всегда
  истинным; повторный запрос с изменившимся candidate принимается как «уже
  ожидающий»;
- `pkg/checks/checks.go:652` — режим файла удаляется из workspace digest,
  `chmod +x` между проверкой и доставкой становится невидим;
- `pkg/checks/checks.go:580` — `VerifyResultDigest` сводится к «не пусто»;
- `pkg/evidence/resumeverify.go:126` — дайджест attempt-манифеста при resume;
- `pkg/evidence/anchor.go:179` — дайджест манифестов в anchor;
- `pkg/evidence/store.go:331` — `0444` у immutable-снимков;
- `pkg/evidence/store.go:433` — `IsTestEvidence` не требуется ни одним тестом:
  delivery может пройти на не-тестовом evidence;
- `pkg/redact/scanner.go:183,191` — фильтр плейсхолдеров и порог длины не несут
  тестового веса: все негативные фикстуры короткие и без цифр.

**Закономерность, которую стоит чинить системно.** Выжившие группируются вокруг
формы «проверка, которая срабатывает второй»: где два guard'а защищают одно
свойство, первый протестирован, а до второго тест структурно не доходит. Плюс
вторая форма: тест назван по свойству, но вход построен так, что проверяемое и
фактическое совпадают **по построению**.

Правило, закрывающее обе: для каждого предиката безопасности нужен хотя бы один
тест, где этот предикат — единственное, что может отвергнуть вход.

## QS-16. Окружение разработчика молча подменяет встроенных агентов

Реестр берёт первый слой: проект → `AI_TEAM_AGENT_PATH` → пользовательский
конфиг → встроенные. E2e передаёт подпроцессам всё родительское окружение.

Слой `os.UserConfigDir()` читает реальный каталог разработчика без возможности
отключения. У двух людей с разными локальными настройками тесты дают разный
результат. **S–M.**

## QS-23. `delivery.json` назван tamper-evident, но не проверяется

## QS-24. `containment.json` утверждает наблюдение, которого не было

`pkg/containment/containment.go:136-141` записывает `"cleanup_verified": true`

**M** за реальную проверку.
