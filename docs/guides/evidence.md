# Проверить и передать результат

Каждый прогон оставляет [доказательства](../start/concepts.md#доказательства) (evidence):
что запускалось, какие проверки прошли, кто и что подтвердил. Здесь вы
узнаете, где они лежат, как убедиться, что их никто не менял, и как передать
их коллеге или аудитору без секретов.

> [!LEARN]
> - что лежит в `.ai-team/` и что из этого можно удалять;
> - как посмотреть сводку прогона и проверить его целостность;
> - как собрать переносимый пакет и подписать его;
> - как найти секреты в доказательствах до отправки;
> - как безопасно убрать накопившиеся файлы.

## Что понадобится

- Завершённый прогон и его `run_id`. Идентификатор печатается в выводе
  `ai-team run` и виден в [дашборде](dashboard.md); список всех прогонов —
  каталоги в `.ai-team/runs/`.
- Для подписи — ключ ed25519, например созданный через `openssl`.

## Где лежит состояние

| Путь в проекте | Что там | Можно ли менять |
|---|---|---|
| `.ai-team/config.yaml` | Конфигурация конвейера и проверок | Да, это ваш файл |
| `.ai-team/runs/<run_id>/` | Неизменяемые доказательства прогона | Нет |
| `.ai-team/state/runs/<run_id>.json` | Текущая точка остановки прогона, нужна для `--resume` | Нет, это рабочее состояние контроллера |
| `.ai-team/state/approvals/<run_id>/` | Запросы подтверждений и решения по ним | Нет |
| `.ai-team/state/usage/<run_id>.json` | Worker-supplied итоговая сводка usage, сохранённая bubblewrap cloud-контроллером | Нет |
| `.ai-team/state/exports/` | Записи о проверенных экспортах | Нет |
| `.ai-team/worktrees/<run_id>/` | Каталог [кандидата](../start/concepts.md#кандидат) (candidate worktree) | Не трогайте, пока нужны `--resume` или `deliver` |
| `.ai-team/artifacts/<feature>/` | Рабочие артефакты агентов: спецификации, дизайн, ревью | Читать можно; это не доказательство |
| `.ai-team/reports/<feature>/index.html` | HTML-отчёт по прогону | Открывается в браузере |
| `.ai-team/exports/` | Пакеты экспорта по умолчанию | Да |
| `.ai-team/web.db` | База дашборда | Да, это проекция для отображения |

Внутри `.ai-team/runs/<run_id>/`:

| Файл или каталог | Содержимое |
|---|---|
| `run.json`, `config.json`, `workflow.json` | Параметры прогона, конфигурация и маршрут на момент старта |
| `events.jsonl` | Журнал событий: каждое событие ссылается на хеш предыдущего |
| `attempts/<attempt_id>/` | Манифест попытки этапа, его входы и выходные артефакты |
| `logs/` | Логи runtime по попыткам |
| `reports/`, `candidate.json` | Неизменяемые отчёты и candidate evidence прогона |
| `usage.json` | Сводка токенов и этапов (локальные CLI runs; cloud сводка хранится в `.ai-team/state/usage/`) |
| `containment.json` | Фактический профиль и оси containment (локальные CLI runs; cloud receipt хранится в `.ai-team/state/containment/`) |
| `delivery.json` | Итог delivery, если она была |
| `attestation.json`, `anchor.json` | Сводная аттестация и якорь; появляются, когда прогон завершён |

> [!WARNING]
> Не редактируйте evidence в `.ai-team/runs/` и controller records в
> `.ai-team/state/`, даже чтобы обойти ошибку. `verify` сверяет контролируемые
> records и откажет, если покрытый файл или record не совпадает с сохранёнными
> привязками.

## 1. Посмотреть сводку прогона

```bash
ai-team usage <run_id>
```

```text
Входные токены: нет данных
Выходные токены: нет данных
Всего токенов: нет данных
Доля подписки (приблизительно): оценка недоступна
```

Команда показывает только токены. `нет данных` означает, что runtime не
сообщил полный usage; это не нулевой расход. При заданной месячной стоимости
подписки команда дополнительно показывает приблизительную долю, распределённую
по токенам среди полностью учтённых запусков этого UTC-месяца. Это не цена API;
если данных не хватает, выводится `оценка недоступна`. Уровни изоляции описаны
в [Границе безопасности](../reference/security.md).

Сводка есть только после финализации прогона. Для bubblewrap cloud runs команда
читает `.ai-team/state/usage/<run_id>.json`, если controller создал reservation
этого run до spawn; при reservation отсутствие или повреждение envelope — ошибка.
Worker не видит каталог в sandbox. Loopback API workers без bubblewrap используют
обычный target-file summary, который не считается controller-owned. Локальный CLI сохраняет прежний
`.ai-team/runs/<run_id>/usage.json`.

## 2. Проверить целостность прогона

```bash
ai-team verify --target /path/to/project <run_id>
```

```text
✓ Run 20261006T141426.383969000Z-ae522603a9518b5a: anchor OK — run manifest, event chain, attempt artifacts, supplemental evidence и attestation v1 согласованы
✓ Run OK
```

Команда пересчитывает хеши `run.json`, журнала событий, манифестов попыток,
artifact inputs/outputs и supplemental evidence (логи, reports, candidate,
usage, containment), а также проверяет delivery record, если он есть. Код 0 —
всё согласовано, код 1 — что-то не сходится или прогон ещё не завершён
(`run <run_id> не terminal`).

## 3. Проверить, нет ли секретов

До отправки доказательств наружу проверьте их на секреты:

```bash
ai-team redact scan --run <run_id>
ai-team redact verify --run <run_id>
```

`scan` перечисляет находки и всегда завершается с кодом 0:

```text
  .ai-team/runs/<run_id>/logs/…-001-analyst.log:7 AKIAIOSFODNN7EXAMPLE (aws access key)
  .ai-team/runs/<run_id>/logs/…-001-analyst.log:7 ghp_abcd…6789 (github token)
✓ Scan: 57 files, 2 findings, 0 unscanned
```

Если часть файла просканировать не удалось (например, JSON не разобрался или вложен слишком глубоко),
обе команды печатают предупреждение `⚠ Не просканировано: …` с перечнем мест.
Такой файл нельзя считать чистым, даже если находок нет: проверьте его вручную.

`verify` возвращает код 1, если что-то нашлось:

```text
✗ Redaction …/.ai-team/runs/<run_id>: redaction: 2 violations в 1 файлах
```

Без `--run` обе команды проверяют все прогоны в `.ai-team/runs/`. Флаг
`--path` ограничивает проверку одним путём внутри проекта.

Чтобы получить копию с заменёнными секретами, выполните:

```bash
ai-team redact redact --run <run_id> --out /tmp/redacted-run
```

Секреты в копии заменяются метками вида `[REDACTED:github token]`. Исходные
файлы не меняются. По умолчанию копия пишется в `.ai-team/redacted`.

> [!IMPORTANT]
> Поиск секретов ищет известные форматы ключей и токенов. Он не находит
> всё: пароль в свободной форме или внутренний токен нестандартного вида
> пройдут незамеченными. Считайте его дополнительной страховкой, а не
> гарантией.

## 4. Собрать переносимый пакет

```bash
ai-team export --target /path/to/project --out /path/to/new-bundle <run_id>
ai-team verify /path/to/new-bundle
```

```text
✓ Run 20261006T141426.383969000Z-ae522603a9518b5a проверенно экспортирован
  bundle:        /path/to/new-bundle
  bundle_sha256: 93222278…59323
  verified:      state/exports/20261006T141426.383969000Z-ae522603a9518b5a.json (разрешает gc --prune-runs)
```

`export` работает только для завершённого прогона. Сначала он сам проверяет
целостность и секреты; если секреты нашлись, экспорт отказывает:

```text
✗ Export blocked: evidence run <run_id> содержит секреты: redaction: 2 violations в 1 файлах
```

В пакет попадают только типизированные записи: `run.json`, `config.json`,
`workflow.json`, `events.jsonl`, манифесты попыток, аттестация, якорь и
`index.json` с хешами всех файлов. Логи runtime и содержимое артефактов в
пакет не входят. Проверка пакета через `ai-team verify <каталог>` не требует
ни исходного репозитория, ни `.ai-team`.

Каталог `--out` должен быть новым: в существующий каталог экспорт не пишет
(`bundle … уже существует`). Без `--out` пакет попадёт в
`.ai-team/exports/<run_id>.bundle`.

## 5. Подписать пакет

Подпись подтверждает, кто выпустил пакет. Создайте пару ключей ed25519 и
храните закрытый ключ отдельно от проекта:

```bash
openssl genpkey -algorithm ed25519 -out signing-key.pem
openssl pkey -in signing-key.pem -pubout -out signing-key.pub
```

Подпишите при экспорте и проверьте с открытым ключом:

```bash
ai-team export --out /path/to/signed-bundle --sign-key signing-key.pem <run_id>
ai-team verify --verify-key signing-key.pub /path/to/signed-bundle
```

```text
✓ Bundle /path/to/signed-bundle: OK — records, event chain, anchor, attempt artifacts, delivery/containment records и attestation v1 согласованы — подпись DSSE ed25519 подтверждена
✓ Bundle OK
```

Подпись лежит в `dsse.json` внутри пакета. Если передать `--verify-key`, а
подписи нет, `verify` откажет: `задан --verify-key, но dsse.json (подпись
bundle) отсутствует`. Пакеты `ai-team gate` подписываются так же: флаг
`--sign-key` у `gate`.

> [!DEEPDIVE] Целостность и подлинность — не одно и то же
> `ai-team verify` без ключа проверяет **целостность**: записи пакета
> согласованы между собой, хеши сходятся, журнал событий не разорван. Если
> кто-то изменит один файл, проверка это заметит:
> `record run_manifest run.json не совпадает со своим sha256 (evidence подменён)`.
>
> Но целостность не говорит, **кто** создал пакет. Тот, у кого есть доступ к
> файлам, может собрать новый согласованный пакет с нуля, и он тоже пройдёт
> проверку. Поэтому без ключа вывод честно предупреждает:
> `без верификации подписи: --verify-key не задан`.
>
> **Подлинность** даёт только подпись: `verify --verify-key` подтверждает, что
> пакет подписан закрытым ключом, парным вашему открытому. Это имеет смысл,
> если открытый ключ получен из доверенного источника, а закрытый хранится
> вне машины, где работают агенты. Модель угроз описана в
> [Граница безопасности](../reference/security.md).

## 6. Убрать накопившееся

Каталоги кандидатов и рабочее состояние растут с каждым прогоном. Сначала
посмотрите план уборки:

```bash
ai-team gc --dry-run
```

```text
Категория      Объектов           Байт
worktrees             2          36738
Итого                 2          36738
dry-run: ничего не удалено
```

Затем выполните его без `--dry-run`. Что удаляется:

- каталоги кандидатов всех завершённых прогонов — сразу, независимо от
  возраста;
- рабочее состояние (`state/`) завершённых прогонов старше `--older-than`
  (по умолчанию `720h`), кроме `--keep-last` самых свежих (по умолчанию 20);
- доказательства из `.ai-team/runs/` — только с флагом `--prune-runs`, по тем
  же правилам возраста и только для прогонов, у которых есть проверенный
  экспорт. Остальные пропускаются с пометкой `evidence не проверенно
  экспортирована`.

> [!CAUTION]
> Если delivery прогона не удалась и вы собираетесь повторить её через
> `ai-team deliver`, не запускайте `gc` до этого: уборка удалит каталог
> кандидата, и повтор delivery станет невозможен. Храните экспортированные
> пакеты и открытые ключи отдельно от проекта, который чистите.
