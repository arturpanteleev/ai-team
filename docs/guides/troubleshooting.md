# Остановки и BLOCKED

Прогон ai-team останавливается, когда продолжать небезопасно или нужен
человек. Это нормальная часть работы, а не авария. Здесь собраны частые
остановки: какой симптом вы видите, почему так вышло и что сделать.

> [!LEARN]
> - как по коду выхода понять, что произошло;
> - как продолжить остановленный прогон и когда нужно начинать новый;
> - что проверить до запуска, чтобы не упереться в остановку;
> - как разобрать каждую частую остановку.

## Понять, что произошло, по коду выхода

| Код `ai-team run` | Что это значит | Что делать |
|---|---|---|
| `0` | Прогон завершён | Прочитать итог и результат поставки, сохранить доказательства |
| `1` | Ошибка, отказ проверки или отрицательный вердикт | Найти причину в последней строке `✗ Пайплайн остановлен: …` |
| `2` | BLOCKED: контроллер не может продолжить безопасно | Устранить указанную причину |
| `3` | Нужно решение человека или прогон остановлен пользователем | Принять решение и продолжить через `--resume` |

Последняя строка вывода всегда начинается с `✗ Пайплайн остановлен:` и
содержит причину. Подробная таблица статусов — в справочнике
[Статусы и коды выхода](../reference/statuses.md).

## Перед запуском

Большую часть остановок можно предупредить заранее.

1. Работайте в доверенном репозитории и проверьте, что `git status --short`
   ничего не выводит.
2. Убедитесь, что выбранный runtime (OpenCode, Codex или Claude Code) есть в
   `PATH` и получает нужные ключи (см. ниже).
3. Прочитайте `.ai-team/config.yaml`: какие [проверки](../start/concepts.md#проверки)
   обязательны и для каких этапов.
4. Если нужна поставка, проверьте Git identity, `remote origin` и `gh auth
   status`.
5. Берите небольшую задачу с проверяемым результатом и запишите SHA сборки
   `ai-team`.

Перед каждым прогоном ai-team печатает отчёт готовности:

```text
  ✓ cli (required): 1.18.33
  ! model: model/provider выбирает opencode
  ! credentials: явные credential environment variables не разрешены
  ✓ git_repository (required): /path/to/project
  ✓ git_branch (required): main
  ✗ delivery_remote (required): remote origin не настроен
  ✓ github_auth (required): gh authentication доступна
```

CLI отказывается стартовать только при провале `cli`. Пункты про Git, remote и
`gh` нужны для поставки: при их провале прогон начнётся, но остановится на
этапе поставки. Дашборд строже и не запускает прогон, пока не пройдены все
обязательные пункты.

## Продолжить остановленный прогон

Незавершённый прогон продолжают по его идентификатору (`run_id`), который
печатается в выводе:

```bash
ai-team run --target /path/to/project --resume <run_id>
```

При продолжении сохраняется тот же `run_id`, ai-team перепроверяет
доказательства и продолжает нумерацию попыток. Если прогон ждёт
подтверждения плана поставки, добавьте `--approve-plan` с проверенным SHA-256
(см. [ниже](#прогон-ждёт-подтверждения-код-3)).

Завершённый прогон продолжить нельзя:

```text
✗ Пайплайн остановлен: resume run: run <run_id> уже terminal
```

Завершёнными считаются прогоны, остановленные отказом проверки, отрицательным
вердиктом или BLOCKED. После исправления причины начните новый прогон с
`--feature` и `--task`. Исключение — неудавшаяся поставка после завершения,
для неё есть `ai-team deliver` (см. [ниже](#поставка-не-удалась-после-подтверждения)).

## Частые остановки

### Грязное рабочее дерево

**Симптом.** `ai-team run` завершается с кодом 1:

```text
✗ Пайплайн остановлен: candidate требует clean git workspace
```

`ai-team gate` с `--candidate HEAD` возвращает код 2:

```text
✗ Gate: BLOCKED: Git working tree содержит untracked-файлы вне .gitignore (…): report.xml
```

**Причина.** Контроллер строит [кандидата](../start/concepts.md#кандидат) (candidate
worktree) от последнего коммита. Незакоммиченные или неотслеживаемые файлы
в него не попадут, и контроллер отказывается делать вид, что их нет.

**Что сделать.** Закоммитьте или уберите изменения (`git stash -u`). Отчёты
тестов и кеши, которые создают проверки, добавьте в `.gitignore`.

### Runtime не найден

**Симптом.** Код 2 сразу после отчёта готовности:

```text
  ✗ cli (required): команда opencode не найдена в PATH
✗ Preflight: preflight failed: cli: команда opencode не найдена в PATH
```

**Причина.** В конфигурации указан runtime, которого нет в `PATH` того
процесса, где запущен `ai-team`. По умолчанию это `opencode`.

**Что сделать.** Установите runtime или поменяйте поле `cli` в
`.ai-team/config.yaml` на `codex` или `claude`. Проверьте `opencode --version`
(или `codex --version`, `claude --version`) в том же терминале. Если CLI
запускается из сервиса или CI, проверьте `PATH` именно там.

### Ключи провайдера не доходят до runtime

**Симптом.** Отчёт готовности предупреждает:

```text
  ! credentials: явные credential environment variables не разрешены
```

Затем этап агента падает с ошибкой авторизации провайдера, хотя тот же CLI
в вашем терминале работает.

**Причина.** Контроллер запускает runtime в изолированном окружении. Туда
попадают только базовые переменные (`PATH`, `HOME`, `LANG`, `TMPDIR` и
несколько других) и переменные, которые вы явно разрешили по имени.

**Что сделать.** Перечислите имена нужных переменных через запятую в
`AI_TEAM_HARNESS_ENV_ALLOW`:

```bash
# ANTHROPIC_API_KEY уже задан в окружении безопасным способом.
export AI_TEAM_HARNESS_ENV_ALLOW=ANTHROPIC_API_KEY
ai-team run --feature greet --task "Добавить приветствие по имени"
```

Тогда отчёт покажет `✓ credentials: заданы: ANTHROPIC_API_KEY`, а если
переменной нет в окружении — `отсутствуют: ANTHROPIC_API_KEY`. Значение
разрешённой переменной передаётся в runtime как есть; сам ai-team не пишет его
в логи и доказательства прогона. Не храните ключи в конфигурации, промптах и
Git. Подробнее — [Конфигурация: runtime и ключи](../reference/config.md#runtime-и-ключи).

> [!WARNING]
> Разрешение по имени ограничивает, какие переменные видит runtime, но не
> гарантирует, что модель или CLI никогда не выведут значение в лог. Перед
> передачей доказательств наружу выполните `ai-team redact verify` — см.
> [Проверить и передать результат](evidence.md).

### Агент вернул BLOCKED

**Симптом.** Код 2:

```text
ai-team [analyst] ⊘ BLOCKED: требования противоречивы

⊘ Блокер: требования противоречивы
  Для исправления уточните задачу и запустите заново: ai-team run --feature blk --task "<описание>"
…
✗ Пайплайн остановлен: агент analyst заблокирован: требования противоречивы
```

**Причина.** Агент решил, что задачу нельзя выполнить: требования
противоречат друг другу или их слишком мало. Он сообщил об этом файлом
`.ai-team/artifacts/<feature>/status/<agent>.md` со строками
`**Status:** BLOCKED` и `**Blocker:** <причина>`.

**Что сделать.** Прочитайте причину, уточните описание задачи и запустите
новый прогон, как подсказывает вывод. Прогон с BLOCKED завершён, `--resume`
его не продолжит.

### Прогон ждёт подтверждения (код 3)

**Симптом.** В неинтерактивном запуске (CI, скрипт, ввод не из терминала)
прогон останавливается с кодом 3. Перед поставкой ai-team печатает план
поставки и готовые команды:

```text
Plan SHA-256: f19b6297…71d4a8
Решение: ai-team decision --run <run_id> --approval approval-f018… --actor <id> --role release_manager --action approve|reject --subject f19b6297…71d4a8
Для продолжения с явным подтверждением плана: ai-team run --resume <run_id> --approve-plan f19b6297…71d4a8
✗ Пайплайн остановлен: delivery перед deployer: требуется решение человека (run=… approval=… subject=…)
```

**Причина.** Перед commit, push и PR нужно явное подтверждение именно этого
[плана поставки](../start/concepts.md#план-поставки) (canonical delivery plan). В
интерактивном терминале ai-team спрашивает `Продолжить? [y/N]`, без терминала
— останавливается и ждёт.

**Что сделать.** Прочитайте план: список файлов, ветку, сообщение коммита и
текст PR. Затем выберите один способ:

- подтвердить и продолжить одной командой:

  ```bash
  ai-team run --resume <run_id> --approve-plan <sha256-из-вывода>
  ```

- записать решение отдельно и продолжить:

  ```bash
  ai-team decision --run <run_id> --approval <approval_id> --actor alice \
    --role release_manager --action approve --subject <sha256-из-вывода>
  ai-team run --resume <run_id>
  ```

- нажать кнопку решения в [веб-дашборде](dashboard.md) и затем **Resume**.

Ответ `reject` (или `N` в терминале) останавливает прогон с кодом 3, и
поставки не будет.

> [!PITFALL]
> Остановка с кодом 3 бывает и на других переходах, например когда ревьюер
> вернул `CHANGES_REQUESTED`:
> `переход reviewer → coder: требуется решение человека (run=… approval=… subject=…)`.
> Здесь ai-team не печатает готовую команду `decision`. Роль и допустимые
> действия лежат в `.ai-team/state/approvals/<run_id>/<approval_id>.json`
> (поля `required_roles` и `actions`, например `return_to_coder`,
> `override_approve`, `reject`). Проще всего принять такое решение в
> дашборде: там у каждого перехода есть кнопки с нужной ролью.

Роль в `decision` должна совпадать с ролью перехода. Иначе команда завершится
с кодом 1: `Решение отклонено: решение содержит недопустимого actor, role или
action`.

### План изменился

**Симптом.** Код 1 при продолжении:

```text
✗ Пайплайн остановлен: resume run: --approve-plan 0000…0000 не совпадает с subject approval f19b6297…71d4a8
```

или `resume approval: candidate identity changed after decision request`.

**Причина.** Подтверждение привязано к SHA-256 конкретного плана и к
конкретному кандидату. SHA от другого прогона, опечатка или изменённый после
запроса кандидат делают подтверждение недействительным.

**Что сделать.** Скопируйте SHA из вывода этого же прогона и проверьте план
ещё раз. Не берите SHA из другого прогона и не правьте файлы в
`.ai-team/runs/` и `.ai-team/state/`, чтобы обойти проверку.

### Проверка не прошла

**Симптом.** Код 1:

```text
ai-team [tester] ✗ агент tester: детерминированные проверки: required check always-fail failed: exit status 1 (800ms)
…
✗ Пайплайн остановлен: агент tester: детерминированные проверки: required check always-fail failed: exit status 1
```

**Причина.** Упала обязательная проверка этапа: команда вернула ненулевой
код, в JUnit-отчёте есть упавшие тесты, команда не найдена или изменила
рабочее дерево.

**Что сделать.** Запустите ту же команду руками в каталоге кандидата
(`.ai-team/worktrees/<run_id>`), исправьте причину и начните новый прогон.
Если причина `check изменил workspace; verification commands должны быть
read-only` или `tool <имя> unavailable`, исправьте описание проверки — см.
[Настроить проверки проекта](project-checks.md).

### Поставка запрещена без тестов

**Симптом.** Код 1 на этапе поставки:

```text
✗ Пайплайн остановлен: агент deployer: delivery запрещён: нет успешно выполненного required check класса unit/integration/e2e для точного текущего workspace digest c0a3…e229
```

**Причина.** Ни одна обязательная проверка с тестами не прошла для текущего
состояния кандидата. Проверки с адаптером `command` здесь не засчитываются.

**Что сделать.** Добавьте обязательную проверку класса `unit` с адаптером
`go-test-json` или `junit-xml` — см. [Настроить проверки проекта](project-checks.md).

### Поставка не удалась после подтверждения

**Симптом.** Код 1 после подтверждения плана:

```text
✗ Пайплайн остановлен: deferred delivery: controller.Execute: delivery create_pull_request failed: exit status 1
```

**Причина.** План подтверждён, но commit, push или создание PR не прошли:
нет доступа к remote, `gh` не авторизован, сеть недоступна.

**Что сделать.** Устраните причину и повторите только поставку:

```bash
ai-team deliver --run <run_id> --target /path/to/project
```

`deliver` заново сверяет подтверждённый план с кандидатом, берёт блокировку и
записывает итог поставки. Произвольный diff без подтверждения так доставить
нельзя.

> [!CAUTION]
> Не запускайте `ai-team gc` до успешного `deliver`. Уборка удаляет каталоги
> кандидатов всех завершённых прогонов, и после неё `deliver` не сможет найти
> рабочую копию: `deliver: workspace lock: lstat …/.ai-team/worktrees/<run_id>: no such file or directory`.

### Другие сообщения

| Сообщение | Что проверить |
|---|---|
| `Ошибка загрузки конфига: …` | Синтаксис и значения в `.ai-team/config.yaml`; текст ошибки указывает поле |
| `проект не инициализирован … — сначала выполните ai-team init` | Команда запущена не в том каталоге или без `--target` |
| `агент coder не создал изменений в коде` | Задача не привела к изменениям; уточните её |
| `resume run: config/workflow identity mismatch` | Конфигурацию изменили после старта прогона; верните её или начните новый прогон |
| `resume approval: candidate worktree отсутствует` | Каталог кандидата удалён или перемещён; начните новый прогон |
| `delivery: …не совпадает с approved plan…` | Ветка, коммит или набор файлов отличаются от подтверждённого плана; не меняйте кандидата вручную |
| `remote origin не настроен`, `gh authentication недоступна` | Предусловия поставки; для gate они не нужны |

## Если причина неясна

Откройте [issue](https://github.com/arturpanteleev/ai-team/issues) и
приложите SHA сборки `ai-team`, команду, `run_id` и вывод без секретов. Не
прикладывайте сырые логи runtime: в них могут оказаться ключи.
