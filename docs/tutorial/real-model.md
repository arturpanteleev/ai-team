# 4. Подключить настоящую модель

До сих пор вместо модели работали заглушки. Здесь вы уберёте их, подключите настоящий агентный CLI — OpenCode, Codex или Claude Code, — передадите ему ключ провайдера и проведёте первую настоящую задачу на своём репозитории.

> [!LEARN]
> - как убрать заглушки из учебного режима
> - какой CLI выбрать и как `ai-team` его находит
> - как передать ключ провайдера в изолированное окружение агента
> - как настроить `cli` и `model` в `.ai-team/config.yaml`
> - чем первая настоящая задача отличается от учебной

> [!WARNING]
> `ai-team` работает в режиме trusted-local (см. [Ключевые понятия](../start/concepts.md#trusted-local)). Агент и проверки запускаются на вашей машине с вашими правами. Контроллер ограничивает агента: отдельная копия репозитория, запрет на чтение `.env` и ключей, фильтр переменных окружения. Но это не песочница: не запускайте `ai-team` на недоверенном или чужом коде и не держите рядом секреты, которые агенту видеть нельзя. Подробно — [Граница безопасности](../reference/security.md).

## 1. Убрать заглушки

Откройте новое окно терминала: в старом `PATH` начинается с каталога заглушек. Проверьте, что `opencode` и `gh` больше не указывают в `ai-team-tutorial/mockbin`:

```bash
command -v opencode gh
```

Если учебный каталог больше не нужен, удалите его: `rm -rf "$HOME/ai-team-tutorial"`.

## 2. Выбрать агентный CLI

`ai-team` не ходит к модели сам. Он запускает один из агентных CLI, а тот уже говорит с провайдером. Каждый CLI ставится и настраивается отдельно от `ai-team`:

| CLI | Значение `cli:` | Установка | Проверка |
|---|---|---|---|
| OpenCode | `opencode` (по умолчанию) | [opencode.ai/install](https://opencode.ai/install) + хотя бы один провайдер, см. [opencode.ai/docs](https://opencode.ai/docs) | `opencode --version` |
| Codex | `codex` | [github.com/openai/codex](https://github.com/openai/codex) | `codex --version` |
| Claude Code | `claude` | [docs.anthropic.com](https://docs.anthropic.com/en/docs/claude-code) | `claude --version` |

Убедитесь, что выбранный CLI есть в `PATH` и отвечает на `--version`. Ровно эту команду выполнит проверка окружения перед прогоном, строка `cli (required)`.

Прежде чем подключать к `ai-team`, убедитесь, что CLI сам по себе работает: задайте ему простой вопрос в обычном терминале.

## 3. Передать ключ провайдера

`ai-team` запускает агента в изолированном окружении. У CLI свой временный каталог настроек на время запуска: у OpenCode — `XDG_CONFIG_HOME`, у Codex — `CODEX_HOME`, у Claude Code — `CLAUDE_CONFIG_DIR`. Из ваших переменных окружения агент получает только базовые (`PATH`, `HOME`, `USER`, `LANG`, `TMPDIR`, `TERM` и подобные) и те, что вы разрешили по имени.

Поэтому ключ в вашем шелле ещё не значит, что агент его увидит. Прогон оборвётся на авторизации, хотя тот же CLI в том же окне работает. Разрешите переменную по имени через `AI_TEAM_HARNESS_ENV_ALLOW` — список имён через запятую:

```bash
export ANTHROPIC_API_KEY='<ваш ключ>'
export AI_TEAM_HARNESS_ENV_ALLOW=ANTHROPIC_API_KEY
```

Агент получит переменную с её значением. `ai-team` не пишет значение в логи и доказательства прогона, но сам агентный CLI может его вывести. Старое имя `AI_TEAM_OPENCODE_ENV_ALLOW` работает так же.

Какая переменная нужна, зависит от CLI и провайдера:

| CLI | Переменная |
|---|---|
| Claude Code | `ANTHROPIC_API_KEY` |
| Codex | `CODEX_API_KEY` |
| OpenCode | переменная выбранного провайдера, см. документацию OpenCode |

> [!NOTE]
> Вход, который CLI сохранил в своём обычном каталоге настроек, агент может не увидеть: на время прогона каталог настроек подменяется временным. Самый предсказуемый путь — ключ в переменной окружения, разрешённой по имени.

Проверка окружения покажет, что вышло:

```text
  ✓ credentials: заданы: ANTHROPIC_API_KEY
```

Если имя разрешено, а переменной нет, строка будет с `!` и словом «отсутствуют». Без `AI_TEAM_HARNESS_ENV_ALLOW` — знакомое по учебному режиму предупреждение «явные credential environment variables не разрешены».

Не храните ключ в `config.yaml`, в описании задачи или в Git. Подробнее — [Конфигурация: runtime и ключи](../reference/config.md#runtime-и-ключи).

## 4. Подготовить свой репозиторий

Возьмите свой Git-проект, которому вы доверяете. Для первого раза подойдёт небольшая задача с понятным тестом. Начните с чистого рабочего каталога:

```bash
cd /path/to/your-repository
git status --short
ai-team init
```

`init` пишет в `.ai-team/config.yaml` поле `cli: opencode`. Если вы выбрали другой CLI, поменяйте его. Там же можно задать модель и уровень усилий:

```yaml
cli: claude          # opencode | codex | claude
model: auto          # пусто или auto — модель выбирает сам CLI
effort: medium       # low | medium | high
```

Эти поля можно переопределить у отдельного этапа в списке `pipeline`, например дать ревьюеру другую модель. Формат имени модели — тот, что понимает ваш CLI. Все поля — в [Конфигурации](../reference/config.md).

Для Go-проекта `init` сам включит проверки `go test` и `go vet`. Для другого стека настройте обязательную проверку вручную, иначе поставка будет запрещена: [Настроить проверки проекта](../guides/project-checks.md).

> [!PITFALL]
> Если в репозитории лежат настройки агентного CLI — `opencode.json`, `opencode.jsonc`, `.opencode/plugins`, `.opencode/tools`, `.codex/config.toml` или `.claude/settings.json`, — прогон откажется запускать агента. Это намеренно: такие файлы могли бы расширить права агента в обход контроллера. Уберите их из проекта или запускайте `ai-team` на копии без них.

## 5. Подключить настоящий gh

Для pull request нужен авторизованный [`gh`](https://cli.github.com) и `origin`, который указывает на GitHub:

```bash
gh auth login
gh auth status
git remote get-url origin
```

Без `gh` проверка окружения покажет `✗ github_auth`, а прогон дойдёт до плана поставки, но открыть PR не сможет. Поэтому настройте `gh` до первой задачи.

## 6. Провести первую настоящую задачу

```bash
ai-team run --feature empty-input --task "Обработать пустой ввод в парсере и добавить тест"
```

Проверьте первые строки вывода: `cli` с версией настоящего CLI, `credentials` с вашей переменной, `github_auth` пройден.

Дальше всё как в учебном режиме, только медленнее и по-настоящему:

- этапы работают минуты, а не миллисекунды, и тратят токены провайдера;
- ревьюер может вернуть код на доработку (`CHANGES_REQUESTED`), тогда кодер получит новую попытку;
- агент может остановиться со статусом BLOCKED, если задача противоречива или ему не хватает данных, — что делать, описано в [Остановках и BLOCKED](../guides/troubleshooting.md);
- в интерактивном терминале в конце будет вопрос `Продолжить? [y/N]`, в CI или с `< /dev/null` — остановка с кодом 3 и подтверждение через `--resume` и `--approve-plan`, как на [шаге 3](approve.md).

Перед ответом `y` прочитайте план поставки и сам код в кандидате `.ai-team/worktrees/<run_id>/`. Теперь это код модели, и подтверждаете его вы.
