# Проектирование

## Контекст

Контрольные данные `.ai-team/` не должны попадать в delivery diff, но
автоматическое изменение tracked-capable `.gitignore` нарушает собственный
baseline guard. Git уже предоставляет локальный exclude-файл, который решает
эту задачу без изменения проектных файлов.

## Решения

### Локальная ignore policy по умолчанию

Для Git-репозитория controller вызывает `git -C <target> rev-parse --git-path
info/exclude`. Это корректно разрешает путь как для обычного репозитория, так и
для linked worktree, не предполагая, что `<target>/.git` является каталогом.
В разрешённый файл идемпотентно добавляется точная строка `.ai-team/`.

Вне Git-репозитория ignore-файл не создаётся: `.ai-team/` всё равно
инициализируется, а Git policy там неприменима.

### Явное изменение `.gitignore`

`ai-team init --write-gitignore` пишет `.ai-team/` в корневой `.gitignore`.
Этот режим нужен, когда команда сознательно хочет разделить правило через
репозиторий. Флаг не включает одновременную запись в `.git/info/exclude`:
одного источника ignore policy достаточно.

### Ошибки и безопасность

Невозможность обеспечить ignore policy в Git-репозитории является ошибкой
`init`, а не предупреждением: успешный `init`, после которого гарантированно
не работает `run`, является ложным успехом. Symlink вместо целевого
ignore-файла отклоняется. Повторный `init` не дублирует правило.

### Проверка регрессии

Unit tests покрывают идемпотентную запись и отказ от symlink. E2E после
`init` проверяет пустой `git status --porcelain`, а затем запускает обычный
pipeline без промежуточного коммита ignore policy.
