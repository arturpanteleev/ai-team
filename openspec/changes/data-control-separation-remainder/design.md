# Data/control separation remainder (OPS-8) — design

## Контекст

Контур контроля строится на двух каналах:

1. **Input**: содержимое upstream-артефактов в промпт — закрыт #22
   (`<UNTRUSTED_ARTIFACT>` delimiters в `pkg/runtime/agentcli.go::buildPrompt`
   и `pkg/eval`).
2. **Output**: контроль-маркеры в файлах артефактов (`**Verdict:**`,
   `**Result:**`, `**Status:** BLOCKED` / `**Blocker:**`) и структурированные
   event'ы адаптеров на stdout. **Этот change закрывает output-сторону.**

## Решение

### 1. Data-region exclusion в `pkg/verdict`

Новая функция:

```go
// StripDataRegions заменяет содержимое data-display-регионов (CommonMark
// fenced code blocks, blockquote) пустыми строками, сохраняя построчную
// структуру и номера строк — line-anchored маркеры вне регионов не меняются.
func StripDataRegions(src string) string
```

Правила:

- **Fenced code block**: строка, открывающая fence `` ``` `` или `~~~` (с
  необязательной info-строкой), далее до закрывающего fence той же длины и
  символа. Незакрытый fence → регион до конца текста (fail-closed к *меньшей*
  интерпретации: содержимое нечитается как control).
- **Blockquote**: строки, у которых после пробельных префикса начинается `>`
  (необязательно с пробелом после `>`). Вложенные fence внутри blockquote
  обрабатываются по своим правилам — блокирующее действие «не читать» касается
  всей цитаты целиком; содержимое внутри цитаты не читается как control
  независимо от вложенных фенсов.
- Замена — пустыми **строками** (а не удаление): маркеры на соседних строках
  не «склеиваются», а line-anchored regex сохраняет свои позиции.

Хирургия:

- `Parse` — применяет strip перед поиском маркеров.
- `FromOutputsContract` — применяет strip к каждому прочитанному файлу; маркер
  внутри data-региона не учитывается в `matches`, и если после strip маркеров
  нет — ошибка «маркер отсутствует» (fail-closed, а не интерпретация).
- `ReadBlocked`/`ReadBlockedSince` — применяет strip до `blockedRe`/`blockerRe`.

Семантика: строка `**Verdict:** REJECTED` внутри фенса/цитаты — это **данные**
(пример, вычитка), а не инструкция; за настоящий вердикт принимается только
маркер вне data-регионов. Детерминированно, без зависимости от модели.

### 2. Adapter surface (ADP-1/2)

Правило: адаптер читает control ТОЛЬКО из собственных, типизированных
event-пространств харнесса; чужой/нетипизированный JSON (включая model-mimic)
игнорируется.

- `codex.ParseUsage` — уже фильтрует `type == "turn.completed"`; добавляем тест:
  строка `{"type":"usage","usage":{...}}` (модельный шум) не принимается,
  последний реальный `turn.completed` выигрывает.
- `claude.lastClaudeResult` — уже фильтрует `type == "result"`; добавляем тест:
  строки `{"type":"text",...}` игнорируются, а поддельный `{"type":"result"}` в
  начале потока перетирается последним реальным result (last wins).

Дополнительных изменений поведения не требуется — закрываем **пробел в
покрытии**, который делает каждый новый адаптер «чёрным ящиком».

## Изменяемые файлы

- `pkg/verdict/verdict.go` — `StripDataRegions` + применение в трёх точках.
- `pkg/verdict/verdict_test.go` — тесты data-регионов.
- `pkg/runtime/codex_test.go`, `pkg/runtime/claude_test.go` — coverage чужих типов.
- `openspec/changes/data-control-separation-remainder/` — delta.

## Риски

- Новая функция может пропустить экзотическую разметку (например, fence без
  закрытия внутри цитаты) — правило «незакрытый fence = до конца» уменьшает
  поверхность ложных интерпретаций.
- Регрессия артефактов: существующие артефакты, где вердикт приведён как
  обычная (не-fenced, не-цитатная) строка, читаются как и раньше — тесты
  contract-пути покрывают прежнее поведение.
