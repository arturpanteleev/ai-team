# Dependency kill-watch tracker (EXP-1) — design

## Решение

Один документ-трекер `docs/DEPENDENCY-KILL-WATCH.md` фиксирует зависимость
signal → action. Табличная форма повторяет существующий kill-анализ из
`FEATURES.cloud.md` §6, но разворачивает каждый сценарий в три обязательные
колонки: сценарий, сигнал раннего обнаружения, действие. Плюс отдельная секция
«Где наблюдать» с конкретными источниками, чтобы проверка была исполнимой, а не
общей.

Интервью-правило остаётся **объективным счётчиком**: 3 подряд «не нужно» или 0
внешних повторных запусков за 8 недель (Signal 4 + интервью) → pivot на Track P.
Порог не меняется в обход теста: контракт-тест требует наличия строк в таблице
и Stop-правила, что делает сокращение определения явным актом.

## Согласованность

- Сигналы соответствуют §«Чего нет ни в codex, ни в ревизии 2»:
  1) GitHub Agent HQ собственная квитанция; 2) харнесы эмитят DSSE/OTel;
  3) «верификация не боль» (интервью ≥3 / 0 повторных запусков за 8 недель);
  4) bundle непонятен (проблема истории — переписывать `verify`, не добавлять
  evidence).
- Действия остаются кодразделы: импортированные внешние attestation для схемы
  v1, агрегация/верификация чужих, pivot на Track P.
- Тест держит документ согласованным, а не дублирует его содержимое.
