# Dependency kill-watch tracker (EXP-1)

## Proposal

**ID**: EXP-1  |  **Trace**: Track V strategic bet (FEATURES.cloud.md §6) —
single-bet risk must be made observable  |  **Priority**: P1

### ЧТО

Структурированный kill-watch трекер для внешних зависимостей Track V: сигналы,
что GitHub/харнесы начинают перекрывать value proposition контура доверия,
плюс интервью-триггер пивота на Track P. Delivery = документ + контракт-тест,
который не даёт трекеру «сдуться» без пересмотра правил.

### ПОЧЕМУ

Вся сводная стратегия висит на одной ставке (external attestation от харнесов
/ форжа). Если GitHub Agent HQ или Claude Code / Codex начнут эмитить
собственный провенанс, ценность смещается с «мы выпускаем доказательство» на
«мы проверяем чужие». Раннее обнаружение — дешёвое и допустимое без
инфраструктуры; потерянный провенанс-трекер = повторный ресёрч через месяцы.

### Скоуп

1. `docs/DEPENDENCY-KILL-WATCH.md`: таблица сценариев kill, сигналов раннего
   обнаружения и действий (включая интервью-правило ≥3 и критерий повторных
   запусков), плюс раздел «Где наблюдать» с указанием источников.
2. `docs/docs_test.go`: контракт-тест, требующий наличия сценариев, сигналов и
   Stop-правил (guard от удаления правил без намерения).

### Критерии приёмки

- Четыре сценария из §«Чего нет ни в codex» + интервью-правило перенесены с
  явными сигналами «как заметить рано» и «что делать».
- Внутренняя ссылка на FEATURES.cloud.md корректна.
- `docs/docs_test.go` зелёный; `go test ./docs/` проходит.
- Не просим согласия владельца (owner decision RQ — уже зафиксирован).

### Похожее / альтернативы

- Только интервью без деревьев сигналов: теряем раннюю детекцию release-note.
- Только release-note watch без интервью: не видим pivot-сигнал «не боль».
- Мы делаем оба и закрепляем контракт-тестом.
