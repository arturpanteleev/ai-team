# Права по функциям, исполнитель и подтверждающий (B-82)

## Why

Решения D18 и R2-5: роли команды — это функции (BO, PO, архитектор,
разработчик, ревьюер, QA, деплойщик), один человек может выполнять несколько;
разделение «исполнитель / подтверждающий» нужно заложить в модель; можно ли
подтверждать свою работу — настраивается. До изменения все действия над этапом
проверялись одной функцией этапа, подтверждающего отдельно задать было нельзя,
а самоподтверждение не ограничивалось.

## Scope

- `pkg/cloudidentity`: матрица «действие этапа × функция» (`take`, `submit`,
  `bypass`, `confirm`), fail-closed; разбор функций участника с синонимами.
- Шаблон: необязательный `approver_function` этапа, отличный от `function`
  с учётом синонимов; `forbid_self_approval` верхнего уровня.
- Граф: сгенерированное подтверждение этапа и возврат требуют роль
  подтверждающего, если он задан.
- Web API: каждое действие этапа проверяется на сервере по функциям
  закреплённого шаблона; `forbid_self_approval` применяется к `confirm` и к
  общему маршруту решений.
- Команда: назначение функций участникам принимает синонимы шаблона.

## Non-goals

- UI-фильтрация доступных действий по функциям участника.
- Запрет самоподтверждения для возврата (`return`): он касается только
  подтверждения.

## Local mode

Локальный режим работает от одного `local-user` со всеми функциями, поэтому
матрица прав его не ограничивает. `forbid_self_approval` по умолчанию
выключен; если его включить, он действует и локально (fail-closed), и
единственный пользователь не сможет подтвердить сданный им результат.
