## ADDED Requirements

### Requirement: Действия этапа разрешаются по функции этапа

Server MUST авторизовать действия над этапом по функциям закреплённого за run
шаблона. Взять этап, сменить исполнителя, запустить агента, сдать результат,
ответить на grill, обойти проверку и пропустить этап MUST разрешаться только
участнику с функцией `function` этапа. Подтвердить этап и вернуть его назад
MUST разрешаться только участнику с функцией `approver_function`, а если она
не задана — с функцией `function`. Проверка MUST быть fail-closed: отсутствие
у участника нужной функции или функция этапа, не сопоставленная ни одной
роли, MUST приводить к отказу 403 без обращения к контроллеру.

#### Scenario: Исполнитель не подтверждает при заданном подтверждающем

- **КОГДА** у этапа `function: developer` и `approver_function: reviewer`, а
  участник имеет только функцию developer
- **ТОГДА** take, submit, override и skip MUST быть разрешены
- **И** confirm и return MUST быть отклонены с 403

#### Scenario: Чужая функция

- **КОГДА** участник не имеет ни функции исполнителя, ни функции
  подтверждающего этапа
- **ТОГДА** любое действие над этапом MUST быть отклонено с 403

#### Scenario: Локальный режим

- **КОГДА** web server работает с локальной аутентификацией
- **ТОГДА** единственный `local-user` MUST иметь все функции, и матрица прав
  MUST NOT ограничивать его действия

### Requirement: Запрет самоподтверждения

Если шаблон задаёт `forbid_self_approval: true`, server MUST отклонять
подтверждение этапа участником, который брал этап или сдавал его результат в
подтверждаемом посещении, через `confirm` и через общий маршрут решений.
Если авторов определить не удалось, подтверждение MUST быть отклонено.
По умолчанию настройка выключена.

#### Scenario: Автор подтверждает свою работу

- **КОГДА** `forbid_self_approval: true` и подтверждающий сдавал результат
  этапа
- **ТОГДА** подтверждение MUST быть отклонено с 403 без записи решения

#### Scenario: Подтверждает другой участник

- **КОГДА** `forbid_self_approval: true` и подтверждающий не брал этап и не
  сдавал его результат
- **ТОГДА** подтверждение MUST быть записано под ролью подтверждающего

### Requirement: Назначение функций участникам

Приглашение и изменение функций участника команды MUST принимать канонические
роли и синонимы функций шаблона (`bo`, `po`, `deployer`) и MUST хранить их как
канонические роли без повторов. Неизвестная функция MUST быть отклонена.

#### Scenario: Синонимы функций

- **КОГДА** администратор назначает участнику `po` и `product_owner`
- **ТОГДА** участник MUST получить одну функцию `product_owner`
