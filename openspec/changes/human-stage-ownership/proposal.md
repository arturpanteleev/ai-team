# Ответственный за human-этап

Для текущего ожидающего human-этапа участник назначенной роли может зафиксировать, что берёт работу. Событие сохраняет ID посещения approval, нового и прежнего ответственных, а задача показывает текущего ответственного и время с момента назначения. Повторный запрос того же участника безопасен при потере HTTP-ответа и не обнуляет таймер; новый approval при возврате на тот же этап начинает новое владение.

Изменение ограничено ручными входными этапами текущего run. Действие проверяет pinned lifecycle checkpoint и ожидающее input approval; оно не назначает владельцев на агентные этапы. Для RBAC canonical role alias используется только при проверке доступа, тогда как исходная функция этапа остаётся в approval и решении.
