## ADDED Requirements

### Requirement: Ответственный текущего human-этапа
Система MUST позволять участнику с ролью, назначенной текущему этапу, взять ожидающий human input этап в рамках run. Взятие MUST быть привязано к текущему `next_stage` в lifecycle checkpoint и к соответствующему pending input approval.

#### Scenario: Первый участник берёт этап
- **ДАНО** run ожидает human input approval для текущего этапа
- **КОГДА** участник с назначенной ролью берёт этот этап
- **ТОГДА** система MUST записать `stage_taken` с идентификаторами участника и этапа и timestamp
- **И** страница задачи MUST показывать участника и прошедшее время с момента взятия

#### Scenario: Другой участник перехватывает этап
- **ДАНО** текущего human-этапа уже держит другой участник
- **КОГДА** участник с назначенной ролью берёт этот этап
- **ТОГДА** система MUST записать `stage_taken` с новым и предыдущим участниками
- **И** проекция задачи MUST показывать нового участника и время от нового взятия

#### Scenario: Повтор запроса тем же участником
- **ДАНО** участник уже держит текущий human-этап
- **КОГДА** тот же участник повторяет запрос взятия
- **ТОГДА** система MUST сохранить первоначальное время и не создавать дубликат события

#### Scenario: Этап больше не ожидает человеческий ввод
- **ДАНО** этап не является текущим ожидающим human input либо его input approval уже решён
- **КОГДА** приходит запрос взять этап
- **ТОГДА** система MUST отклонить запрос и не менять ответственного
