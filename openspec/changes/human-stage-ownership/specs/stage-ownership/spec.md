## ADDED Requirements

### Requirement: Ответственный текущего human-этапа
Система MUST позволять участнику с ролью, назначенной текущему этапу, взять ожидающий human input этап в рамках run. Взятие MUST быть привязано к текущему `next_stage` в lifecycle checkpoint и к соответствующему pending input approval.
Событие `stage_taken` и проекция владельца MUST включать ID этого approval, а повторное взятие MUST быть идемпотентным только в пределах того же этапа, approval и участника. Проверка доступа MUST использовать canonical role alias, сохраняя исходную функцию этапа в `RequiredRoles`, владельце и `Decision.ActorRole`.

#### Scenario: Первый участник берёт этап
- **ДАНО** run ожидает human input approval для текущего этапа
- **КОГДА** участник с назначенной ролью берёт этот этап
- **ТОГДА** система MUST записать `stage_taken` с идентификаторами участника, этапа и approval и timestamp
- **И** страница задачи MUST показывать участника и прошедшее время с момента взятия
- **И** raw функция этапа MUST остаться в роли владельца и human approval

#### Scenario: Другой участник перехватывает этап
- **ДАНО** текущего human-этапа уже держит другой участник
- **КОГДА** участник с назначенной ролью берёт этот этап
- **ТОГДА** система MUST записать `stage_taken` с новым и предыдущим участниками
- **И** проекция задачи MUST показывать нового участника и время от нового взятия

#### Scenario: Повтор запроса тем же участником
- **ДАНО** участник уже держит текущий human-этап
- **КОГДА** тот же участник повторяет запрос взятия
- **ТОГДА** система MUST сохранить первоначальное время и не создавать дубликат события

#### Scenario: Тот же этап посещён повторно по новому approval
- **ДАНО** участник взял этап в рамках approval A, после возврата создан approval B того же этапа
- **КОГДА** участник берёт этап для approval B
- **ТОГДА** система MUST записать новое событие с ID approval B и новым timestamp
- **И** владелец approval A MUST быть скрыт для текущего approval B
- **И** в событии approval B MUST отсутствовать прежний владелец из approval A

#### Scenario: Текущий approval решён, но lifecycle всё ещё ожидает его
- **ДАНО** approval текущего этапа решён отправкой ответа, а lifecycle checkpoint всё ещё указывает на его ID
- **КОГДА** страница задачи строит проекцию владельца
- **ТОГДА** система MUST продолжать показывать владельца этого approval до смены текущего этапа или approval

#### Scenario: Raw stage function использует canonical alias для доступа
- **ДАНО** human approval требует функцию `po`, `bo` или `deployer`
- **КОГДА** участник с canonical ролью `product_owner` или `release_manager` берёт назначенный этап или принимает его approval
- **ТОГДА** система MUST разрешить действие через canonical роль
- **И** `RequiredRoles` и `Decision.ActorRole` MUST сохранить raw функцию этапа

#### Scenario: Этап больше не ожидает человеческий ввод
- **ДАНО** этап не является текущим ожидающим human input либо его input approval уже решён
- **КОГДА** приходит запрос взять этап
- **ТОГДА** система MUST отклонить запрос и не менять ответственного
