# Вход через OIDC и постоянные сессии (B-83)

## Why

Решение D19: в пилоте вход по токенам, SSO подключается позже. Browser
sessions жили в памяти процесса `ai-team web` (`pkg/web/server.go`): перезапуск
выкидывал всех пользователей, отзыв при выходе отсутствовал, а несколько
экземпляров над одной базой не видели сессий друг друга.

## Scope

- `pkg/web/store`: таблицы `web_sessions` (SHA-256 cookie, actor, функции,
  epoch участника, способ входа, created/expires/absolute expiry, revoked) и
  `oidc_login_states` (state → nonce, PKCE verifier, срок). Схема v10; бинарник
  со схемой v9 отказывается открывать такую базу.
- Сессии: 8 часов бездействия со скользящим продлением, не дольше 7 дней;
  `DELETE /api/session` с CSRF отзывает сессию. Сессия локального режима не
  действует в облачном и наоборот. Проверка epoch участника сохраняется.
- `pkg/oidc`: discovery, authorization code + PKCE S256, проверка `id_token`
  (RS256/ES256 по JWKS, issuer, audience/azp, exp/iat/nbf, nonce) без
  сторонних зависимостей. `pkg/oidc/oidctest` — заглушка провайдера для тестов.
- `ai-team web`: `--oidc-issuer`, `--oidc-client-id`, `--oidc-redirect-url`,
  `--oidc-client-secret-env`; секрет клиента только из окружения. OIDC
  включается только вместе с облачной аутентификацией.
- UI: кнопка «Войти через SSO» при включённом SSO и «Выйти».

## Non-goals

- Привязка участника к паре `iss`/`sub`: участник определяется по
  подтверждённому e-mail. `sub` сохраняется в сессии для аудита.
- Создание первого администратора и активация приглашений через SSO: они
  остаются на токенах.
- RP-initiated logout у провайдера.

## Local mode

Не меняется: тот же локальный токен из `.ai-team/web.token` создаёт сессию;
сессия теперь хранится в базе и переживает перезапуск.
