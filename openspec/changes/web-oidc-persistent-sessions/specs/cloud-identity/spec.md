## ADDED Requirements

### Requirement: Постоянные browser sessions

Browser session MUST храниться в базе дашборда, а не в памяти процесса, и
MUST переживать перезапуск сервера. База MUST хранить только digest cookie.
Session MUST истекать после периода бездействия и не позже абсолютного срока;
активность MAY продлевать срок в пределах абсолютного. Отозванная, истёкшая
или неизвестная session, а также session участника, чей epoch изменился,
MUST приводить к `401`. Session, созданная в локальном режиме, MUST NOT
приниматься в облачном режиме и наоборот. Схема базы с сессиями MUST иметь
версию, которую предыдущие бинарники отказываются открывать.

#### Scenario: Перезапуск сервера

- **КОГДА** пользователь вошёл, а сервер перезапущен над той же базой
- **ТОГДА** та же cookie MUST давать ту же session и тот же CSRF token

#### Scenario: Выход

- **КОГДА** пользователь вызывает `DELETE /api/session` с CSRF token сессии
- **ТОГДА** session MUST быть отозвана, и последующие запросы с этой cookie
  MUST получать `401`, в том числе после перезапуска
- **И** запрос выхода без CSRF token MUST быть отклонён с `403`

### Requirement: Вход через OIDC

Если вход через OpenID Connect настроен, облачный server MUST проводить его
как authorization code с PKCE S256. Server MUST привязывать `state` к браузеру
cookie и принимать каждый `state` не более одного раза и только в пределах
срока. `id_token` MUST приниматься только из ответа token endpoint и MUST
проходить проверку подписи по JWKS провайдера (только асимметричные
алгоритмы), точного issuer, audience (и `azp` при нескольких audience),
срока действия и `nonce`. Пользователь MUST определяться по подтверждённому
провайдером e-mail, а его функции MUST браться из назначений активного
участника команды, а не из claims. Любая ошибка проверки, недоступность
провайдера, discovery или JWKS MUST отклонять вход без создания session и без
перехода к другому способу входа. Client secret MUST задаваться только
переменной окружения. В локальном режиме OIDC MUST быть недоступен.

#### Scenario: Успешный вход

- **КОГДА** провайдер вернул действительный `id_token` для активного участника
- **ТОГДА** server MUST создать session с функциями участника из реестра команды

#### Scenario: Подмена или устаревание токена

- **КОГДА** подпись `id_token` не сходится, токен истёк, issuer, audience или
  `nonce` не совпадают
- **ТОГДА** callback MUST вернуть `401` без session cookie

#### Scenario: Подмена state

- **КОГДА** `state` в callback не совпадает с cookie браузера или уже
  использован
- **ТОГДА** callback MUST вернуть `401` без обмена кода

#### Scenario: Сбой провайдера

- **КОГДА** discovery или JWKS недоступны
- **ТОГДА** вход MUST быть отклонён (`503`) без session
