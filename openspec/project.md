# ai-team — контекст проекта

## Что это

Локальный control plane для решения IT-задач цепочкой AI-агентов. LLM
создаёт артефакты (proposal, design, код, тесты, review) и предлагает
вердикты; переходы между этапами, deterministic checks, mutation scopes,
evidence и delivery исполняет детерминированный Go-контроллер — не LLM.

## Замысел

1. Простой цикл разработки: постановка задачи → архитектура → реализация →
   проверка → доставка.
2. Этапы выполняются разными агентами независимо; каждый этап производит
   артефакт-контракт.
3. Workflow задаётся конфигом как граф: вершины — этапы, рёбра — допустимые
   переходы по outcome, approval-политики принадлежат рёбрам.
4. Веб-интерфейс — главная поверхность наблюдения и управления; CLI —
   равноправный транспорт к тому же RunEngine.
5. Каждое значимое решение о переходе санкционирует человек с подходящей
   ролью через exact-subject approval.

## Приоритеты решений

- Детерминизм важен гибкости: если поведение можно исполнить кодом, оно не
  делегируется модели.
- Fail-closed: неизвестное состояние, невалидный вердикт, отсутствующий
  evidence — остановка, а не догадка.
- Controller-owned effects: commit/push/PR выполняет только контроллер после
  подтверждения точного SHA-256 canonical plan.
- Honest evidence: projections (SQLite/web/HTML) восстанавливаемы и никогда
  не переопределяют доменный исход run; source of truth — immutable runs/.

## Границы текущей версии

- Не hermetic sandbox: доверенный локальный проект, права текущего OS-user.
- Typed test adapters реализованы для Go; delivery для других стеков
  заблокирован до появления адаптеров.
- Позиционирование «strict/secure/hermetic» запрещено до закрытия P0-рисков
  из AUDIT.md (OS-sandbox, external anchoring).
