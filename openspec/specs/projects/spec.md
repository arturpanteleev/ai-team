## Purpose

Проект — папка для группировки задач: ID, имя, описание и архивный признак.
Проект не владеет репозиторием, шаблоном, участниками или правами.

## Requirements

### Requirement: Каждая задача принадлежит ровно одному проекту

Run (задача) и элемент бэклога MUST иметь `project_id` существующего проекта.
Создание без `project_id`, с неизвестным проектом или в архивном проекте MUST
быть отклонено до запуска контроллера; решение MUST повторяться атомарно при
admission, чтобы архивирование между проверкой и записью не пропустило задачу.

#### Scenario: Задача без проекта

- **КОГДА** клиент вызывает `POST /api/runs` или `POST /api/backlog` без `project_id`
- **ТОГДА** API MUST вернуть 400 с кодом `project_required`
- **И** задача и run MUST NOT быть созданы

#### Scenario: Неизвестный проект

- **КОГДА** `project_id` не существует
- **ТОГДА** API MUST вернуть 404 с кодом `project_not_found`

#### Scenario: Архивный проект

- **КОГДА** `project_id` указывает на архивный проект
- **ТОГДА** API MUST вернуть 409 с кодом `project_archived`
- **И** история задач архивного проекта MUST оставаться читаемой

#### Scenario: Автоподбор и восстановление

- **КОГДА** подборщик берёт элемент бэклога, а admission pending-run восстанавливается после рестарта
- **ТОГДА** задача MUST сохранить `project_id` элемента или admission-снимка
- **И** если проект к этому моменту заархивирован, элемент MUST получить статус `failed` с причиной, а задача MUST NOT быть создана

### Requirement: Проекты управляются через API без физического удаления

API MUST отдавать список и карточку проекта любому читающему, а создание,
правку и архивирование — только principal с правом `project:manage` (Product
Owner или Architect). Физического удаления проекта MUST NOT быть: архивирование
и возврат из архива идемпотентны и сохраняют задачи.

#### Scenario: CRUD

- **КОГДА** уполномоченный principal вызывает `POST /api/projects`, `PATCH /api/projects/{id}`, `POST /api/projects/{id}/archive` или `.../unarchive`
- **ТОГДА** сервер MUST применить изменение от имени проверенного actor
- **И** имя проекта MUST быть уникальным без учёта регистра в любом алфавите

#### Scenario: Недостаточно прав

- **КОГДА** principal без Product Owner и Architect создаёт или архивирует проект
- **ТОГДА** сервер MUST вернуть 403

#### Scenario: Список

- **КОГДА** клиент вызывает `GET /api/projects`
- **ТОГДА** архивные проекты MUST быть скрыты, пока не передан `include_archived=true`

### Requirement: Старые записи и чистая установка

Миграция схемы MUST создавать проект «Основной» (ID 1) и назначать его всем
существующим run и элементам бэклога без потери данных; чистая установка MUST
получать тот же проект.

#### Scenario: Обновление существующей БД

- **КОГДА** открывается БД до введения проектов
- **ТОГДА** все её run и элементы бэклога MUST принадлежать проекту «Основной»

### Requirement: Фильтр по проекту

`GET /api/runs` и `GET /api/backlog` MUST принимать `project_id`, а Web UI MUST
показывать фильтр проекта на доске и в списке задач и понятную пустую страницу
проекта без задач.

#### Scenario: Задача видна только в фильтре своего проекта

- **КОГДА** задача создана в проекте A, а список запрошен с `project_id` проекта B
- **ТОГДА** задача MUST NOT попасть в ответ
