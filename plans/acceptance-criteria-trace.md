# Acceptance criteria trace (машинная трасса AC)

Статус: идея
Источник: AUDIT H-03

## Задача

Связать acceptance criteria из proposal/spec с доказательствами: каждый AC
получает ID, каждому ID сопоставляются тесты/checks/результаты верификации в
evidence. Контроллер знает не только «тесты зелёные», но и «каждое требование
чем-то подтверждено».

## Ценность для продукта

Главный недоказуемый вопрос автономной разработки: «а всё ли, что требовали,
сделано?» Сейчас ответ — вердикт LLM-верификатора. Машинная трасса делает
его проверяемым: отчёт показывает таблицу «AC → чем подтверждено», и пробел
(требование без evidence) становится видимым до человека, а не после
инцидента. Для продукта это качественный скачок доверия — delivery gate
может требовать полного покрытия AC; для evals — новая метрика качества
агентов (доля AC, закрытых с первого раза).

## Рекомендации по реализации

- schema: секция Acceptance Criteria в proposal-template с обязательными
  стабильными ID (`AC-1`, ...); validate-artifacts проверяет формат;
- маппинг: spec/coder указывают test IDs; controller собирает фактические
  результаты typed checks по этим ID в candidate evidence;
- verifier получает trace + пробелы как вход; delivery precondition:
  нет AC со статусом `not_covered` (или явное обоснование);
- рендер таблицы в HTML-отчёте/вебе.

## Как проверить

1. Фича с 3 AC даёт в evidence trace из 3 записей с evidence digest'ами.
2. Удаление теста, закрывающего AC, ловится на verification (not_covered).
3. Отчёт содержит читаемую таблицу трассы.
