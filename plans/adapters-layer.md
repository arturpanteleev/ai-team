# Adapters layer (адаптеры CLI-агентов)

Статус: idea
Источник: ALK parity — `adapters/`, `docs/adapters/support-matrix.md`

## Задача

Сделать взаимодействие с CLI-агентами uniform. Из кода мы отправляем промпт
агенту, у которого назначено имя инструмента (opencode / codex / claude /
...), и не паримся в рантайме, что это за инструмент — все различия
раскручивает адаптер. Хост = конкретный CLI-инструмент; адаптер именуется по
нему и знает, как его запускать. Первая итерация без моделей и effort — это
отдельная задача (model-routing).

## Ценность для продукта

Сегодня ai-team привязан к одному хосту: если opencode не подходит под задачу
или перестаёт развиваться, продукт теряет применимость целиком. С адаптерами
один и тот же строгий workflow работает поверх любого CLI — это расширяет
аудиторию с пользователей opencode до всех, кто работает с Codex/Claude/
чем угодно, без дублирования детерминированного ядра. Плюс независимость от
вендора: смена хоста = одна строка в def.yaml агента, а не миграция продукта.
Это же фундамент для мультиагентных сценариев: reviewer на одном хосте, coder
на другом.

## Рекомендации по реализации

Точки соприкосновения с opencode сегодня (аудит — unify это всё):

- `pkg/runtime/agentcli.go` (~20 ссылок): сборка команды, prompt-передача,
  изоляция окружения (`OpenCodeIsolationEnvironment`: deny-tools конфиг,
  temp config home, env allow-list) — механизм должен стать контрактом
  адаптера, а не знанием ядра;
- `pkg/preflight/preflight.go`: проверка бинарника/версии → capability check
  адаптера;
- `pkg/config` + `agents/*/def.yaml`: поле `cli` уже есть, откроется
  валидация;
- `pkg/eval/eval.go`: второй независимый запускатель — перевести на общий
  путь;
- `e2etest/mock-opencode.sh`: сделать универсальным мок-адаптером.

Контракт адаптера (черновик): descriptor (имя инструмента, резолвинг
бинарника), command projection (argv + передача промпта + парсинг вывода),
environment boundary (env allow-list, изоляция конфига, deny-rules),
preflight check; регистрация в layered registry рядом с агентами.
Ориентиры: `adapters/` в agent-lifecycle-kit, их support matrix.

## Как проверить

1. Grep "opencode" по pkg/{runtime,preflight,pipeline,config} пуст, кроме
   реестра адаптеров.
2. Один и тот же run проходит на opencode и хотя бы одном другом хосте
   (codex или claude) без изменений ядра — только `cli:` в def.yaml.
3. E2E гоняется с мок-адаптером, имитирующим любой хост.
