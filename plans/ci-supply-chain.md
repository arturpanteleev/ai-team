# CI supply chain (пиннинг и пороги покрытия)

Статус: идея
Источник: AUDIT M-03

## Задача

Зашитить CI: пиновать actions по commit SHA вместо тегов (@v4), явно
задавать `permissions: contents: read`, ввести per-package coverage
thresholds для safety-critical пакетов (pipeline/delivery/evidence/checks/
safeio/approval) вместо агрегатных 60%.

## Ценность для продукта

CI — это машина, которой продукт разрешает исполнять код при каждом push:
мутабельный тег action'а = канал подмены кода, а агрегатное покрытие прячет
нулевое покрытие именно тех пакетов, где живёт безопасность. Пиннинг и
явные permissions — стандарт supply-chain гигиены, который стоит часа работы
и закрывает реальный вектор. Per-package пороги делают честным обещание «
критичный код протестирован»: падение покрытия delivery на 5% перестаёт
тонуть в 60% среднем по проекту. Для внешних контрибьюторов это предсказуемый
gate вместо лотереи.

## Рекомендации по реализации

- все uses: → full-length SHA + комментарий с версией;
- top-level `permissions: contents: read` + точечные повышения по джобам;
- coverage gate скриптом: таблица пакет → порог; safety-critical ≥80%;
- dependabot/renovate для обновления пинов.

## Как проверить

1. В workflow нет мутабельных тегов actions.
2. Джобы не имеют прав больше необходимых (аудит effective permissions).
3. Искусственное снижение покрытия pipeline валит gate с понятной ошибкой.
