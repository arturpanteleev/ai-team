# Dry-run (planning-only режим)

Статус: идея
Источник: ALK parity — `docs/reference/planning-only-launch.md`

## Задача

Режим `ai-team run --dry-run`: скомпилировать граф, резолвнуть агентов и
чеки, показать точный план будущего прогона (этапы, модели, approval-точки,
delivery-условия) — не исполняя ничего и не трогая workspace.

## Ценность для продукта

Сегодня единственный способ проверить конфиг/шаблон — запустить его по-
настоящему: с вызовами LLM, тратой токенов и мутацией git. Dry-run делает
настройку безопасной и мгновенной: отладка шаблонов, ревью профиля перед
большой задачей, проверка «что изменится, если сменить профиль» — всё без
единого токена. Для новичков это первый контакт с продуктом без риска; для
опытных — инструмент планирования («сколько будет стоить эта задача» вместе
с metrics). Также закрывает класс ошибок «конфег валиден, но не так понял».

## Рекомендации по реализации

- переиспользовать CompiledGraph + resolved snapshots (всё уже считается до
  первого LLM-вызова);
- вывод: таблица этапов (agent, host/model из def, checks, approvals на
  исходящих рёбрах, max_visits) + терминалы;
- exit code 0/1 + машиночитаемый JSON для CI-валидации конфигов;
- опционально `--diff`: показать отличия плана от прошлого успешного run.

## Как проверить

1. Dry-run битого конфига перечисляет все ошибки валидации, ничего не создав
   в .ai-team.
2. Dry-run живого конфига показывает ровно те этапы/чеки/approvals, которые
   потом происходят в реальном прогоне.
3. Workspace остаётся чистым (git status пуст).
