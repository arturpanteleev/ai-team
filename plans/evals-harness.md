# Evals harness (протокольная оценка)

Статус: idea

## Задача

Регрессионный корпус для контроллера: golden traces эталонных прогонов +
отрицательные сценарии + метрики из metrics-and-usage. Проверяется не
«хороший ли код написала модель», а соблюдение протокола: порядок переходов,
корректность evidence, fail-closed поведение, resume после обрывов.

## Ценность для продукта

Сейчас любое изменение контроллера/промптов проверяется вручную — регрессии
строгости ловятся только живым прогоном. Evals превращают «нам кажется, что
стало лучше» в числа: protocol violations (=0 обязателен), число loopback-
циклов до APPROVED, токены/время до PR, доля задач дошедших до delivery.
Это же ответ клиентам на вопрос «почему доверять»: публичные метрики
false-acceptance и fail-closed покрытия. Для разработки — свобода рефакторить
ядро, зная, что протокол не сломан.

## Рекомендации по реализации

- инфраструктура уже есть: mock-opencode + e2etest умеют детерминированные
  прогоны; `workflow_trace`/events — машинный эталон пути;
- кейсы: happy path; негативный verdict → loopback → approve; BLOCKED;
  dirty workspace; существующая ветка; tampered evidence; конкурентные
  approvals; kill на каждой boundary + resume;
- сравнение = фактический event trace vs эталонный; метрики из envelope;
- гонять в CI ночных джобой; дельта метрик — в PR описание.

## Как проверить

1. Ночная джоба прогоняет корпус на моках стабильно (флаков нет).
2. Искусственно внесённое нарушение протокола (например, пропуск approval)
   падает на соответствующем кейсе.
3. Отчёт по метрикам прикладывается к каждому PR ядра.
