# Event log anchoring (внешнее якорение)

Статус: идея
Источник: AUDIT H-04

## Задача

Hash chain в events.jsonl защищает от случайной порчи, но владелец файлов
может переписать всю цепочку с новыми хешами. Нужен терминальный manifest с
root hash и опциональный внешний якорь (git-заметка, подпись, timestamping),
который нельзя пересобрать молча.

## Ценность для продукта

Вся ценность «immutable evidence» упирается в вопрос «immutable относительно
кого». Пока якоря нет, строгая система доказательств защищает только от
случайностей — и честный README это признаёт. Внешнее якорирование закрывает
последнюю дыру: спор «агент этого не делал» разрешается проверкой якоря,
независимой от файлов на диске. Для команд/клиентов это переход от
«журналирования» к аттестации; для продукта — право использовать слово
tamper-evident без звёздочек.

## Рекомендации по реализации

- терминальный manifest run'а: root hash всей цепочки + digest всех attempt
  manifests; пишется атомарно при run_finished;
- уровни якоря (по возрастанию силы): копия root hash в SQLite projection;
  git note / commit в отдельную audit-ветку; подпись локальным ключом;
  внешнее timestamping — опционально;
- команда `ai-team verify <run_id>`: replay + сверка якорей;
- replay уже существует (evidence.Resume) — достроить поверх.

## Как проверить

1. Полная подмена events.jsonl с пересчитанными хешами детектируется verify.
2. Удаление попытки/события из середины цепочки детектируется.
3. Якорь проверяется независимо от .ai-team (например, из git note).
