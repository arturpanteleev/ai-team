# Forge adapters (абстракция доставки)

Статус: идея

## Задача

Delivery executor сегодня жёстко завязан на GitHub через `gh` CLI. Нужен
адаптерный контракт к forge-системам: push + создание/статус PR, с
реализациями для GitHub, GitLab, Gitea и bare-remote (push-only без PR).

## Ценность для продукта

Продукт сейчас не работает там, где нет GitHub — а это целые компании и
большая часть self-hosted мира. Даже личные эксперименты упираются: живой
прогон на bare remote требовал обходных путей. Forge-адаптеры открывают эти
аудитории при неизменном ядре гарантий (canonical plan, exact commit,
recovery) — меняется только последний шаг. Дополнительно это чистый
архитектурный выигрыш: граница «git-эффекты vs forge-эффекты» станет явной,
что упростит тестирование доставки моками.

## Рекомендации по реализации

- контракт: prepare → push → create_pr? → status; bare-remote = push-only
  терминал без PR (report честно пишет «PR нет»);
- GitHub остаётся референсной реализацией; GitLab/Gitea по потребности;
- preflight проверяет capability выбранного forge (gh auth / токен GitLab);
- delivery plan schema дополняется полями forge-типа, SHA-подтверждение
  не меняется;
- зависимость: specs delivery-executor обновить дельтой.

## Как проверить

1. E2E на локальном bare remote доходит до delivered без gh в PATH.
2. GitHub-путь регрессионно зелёный (существующие e2e).
3. Неизвестный forge в конфиге отклоняется валидацией до запуска.
