# OpenSpec errata governance (неизменяемый архив)

Статус: идея
Источник: AUDIT M-01

## Задача

Архив openspec/changes/archive правился задним числом — история спецификаций
перестала быть evidence. Ввести правило «архив не редактируется»: исправления
только через errata-change со ссылкой на исходное требование; при
необходимости восстановить затёртую историю из git.

## Ценность для продукта

Продукт продаёт себя идеей доказуемости — и не может позволить собственная
мета-история быть редактируемой задним числом. Это подрывает доверие ко всем
остальным гарантиям: «у них даже спеки переписывают». Неизменяемый архив +
явные errata дают честную эволюцию требований: видно, что требовали тогда,
что уточнили сейчас и почему. Для команды это же дисциплина против тихого
переписывания договорённостей. Дешёвая процессная задача с большим сигналом
зрелости.

## Рекомендации по реализации

- правило в CONTRIBUTING + openspec/project.md: archive = append-only;
- новый тип change `errata`: указывает исходный requirement, что неверно,
  как правильно; валидация make specs проверяет формат;
- аудит текущего архива: сверить с git-историей, оформить найденные
  ретроспективные правки одним errata-документом с атрибуцией.

## Как проверить

1. make specs отклоняет прямой коммит в archive (hook/CI check).
2. Errata-документ валидируется и ссылается на существующий requirement.
3. История архива после внедрения содержит только append-коммиты.
