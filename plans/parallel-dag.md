# Parallel DAG (параллельное исполнение графа)

Статус: идея

## Задача

Граф workflow v4 исполняется строго последовательно. Разрешить независимые
узлы исполняться параллельно: рёбра с разными исходами в разные поддеревья,
join-узел, собирающий результаты веток.

## Ценность для продукта

Типовой выигрыш — независимые проверки и ревью-панель: три ревьюера review-
mesh или независимые чеки идут одновременно, время фичи сокращается на
длительность самой длинной ветки, а не суммы. Для интерактивного цикла это
ощутимая отзывчивость; для дорогих reasoning-моделей — прямая экономия
wall-clock. Плюс это делает граф честным графом, а не списком с loopback'ами.

## Рекомендации по реализации

- компилятор уже строит настоящий граф; добавить анализ независимости узлов
  (нет пути между ними) и планировщик горутин с лимитом;
- evidence: seq остаётся глобальным монотонным; attempt manifests публикуются
  атомарно per-attempt — конфликтов быть не должно, но нужна проверка;
- max_visits/approval semantics для join-узлов продумать отдельно;
- большой кусок: design doc → spike на ветке → реализация;
- риски: гонки за workspace (candidate worktree общий) — возможно,
  потребуется worktree per branch.

## Как проверить

1. Граф с двумя независимыми ветками исполняет их конкурентно (замер времени
   < суммы).
2. Полный race-сьют зелёный; evidence валиден replay'ем.
3. Join-узел получает выходы обеих веток как inputs.
