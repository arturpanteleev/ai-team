# Prompt fingerprinting & runtime identity

Статус: идея
Источник: AUDIT H-08

## Задача

Фиксировать identity всего, что влияет на результат прогона: хеш
def.yaml+prompt.md каждого агента, версию/хеш бинарника CLI-хоста,
provider/model — в attempt manifest. Смена внутри run запрещена; resume
проверяет совпадение.

## Ценность для продукта

Воспроизводимость сегодня иллюзорна: тот же конфиг на другой неделе — это
другие промпты, другая версия opencode, возможно другая модель. Для
инструмента, продающего себя строгими гарантиями, «неизвестно, чем выполнено»
— дыра в доверии. Фингерпринт даёт: честный ответ «этот commit получен
промптом версии X хостом Y»; осмысленные сравнения в evals (иначе метрики
несравнимы); ловлю тихих деградаций (обновился CLI хоста — видно сразу).
Для команд — воспроизводимые инциденты: повторить чужой прогон байт-в-байт
тем же набором входов.

## Рекомендации по реализации

- fingerprint = SHA-256(def.yaml + prompt.md + adapter descriptor + host
  version output) — считать один раз на run;
- attempt manifest дополняется полями; resume сверяет и отказывается при
  несовпадении с явным сообщением «промпт изменился — начните новый run или
  подтвердите --allow-drift»;
- зависимость: adapters-layer даёт version probe хоста.

## Как проверить

1. Модификация prompt.md между попытками видна в evidence и останавливает
   resume без явного флага.
2. Подмена бинарника хоста той же версией-строкой, но другим хешем,
   детектируется.
3. Два прогона с неизменным окружением дают одинаковый fingerprint.
