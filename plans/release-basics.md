# Release basics (лицензия, changelog, теги)

Статус: идея
Источник: docs/audits/2026-08-05-technical-audit.md «Documentation»

## Задача

Минимальный релизный комплект: LICENSE в корне, CHANGELOG.md, семантические
версии с git-тегами и собранными бинарниками (goreleaser или скрипт),
упоминание версии в `ai-team version`.

## Ценность для продукта

Без LICENSE формально никто не имеет права использовать код — это блокер
любого «показать клиентам» и даже публичного обсуждения. Без тегов/changelog
невозможно ни поддерживать пользователей («в какой версии починено?»), ни
вести осмысленный бэклог, ни связывать метрики evals с версиями. Это самый
дешёвый шаг из всех, после которого проект перестаёт быть личным репозиторием
и становится продуктом: ссылку можно давать, версию можно называть,
изменения — трекать.

## Рекомендации по реализации

- LICENSE: выбрать (MIT проще, Apache-2.0 даёт patent-grant — для
  инфраструктурного инструмента лучше Apache);
- CHANGELOG.md по Keep a Changelog; версия — единственный источник в коде;
- CI job: по тегу v* собрать darwin/linux binaries + checksums в GitHub
  Release;
- go install путь уже есть — проверить работу по тегу.

## Как проверить

1. `go install ...@v0.1.0` ставит рабочий бинарник.
2. Release на GitHub содержит артефакты и заметки.
3. `ai-team version` выводит версию, совпадающую с тегом.
