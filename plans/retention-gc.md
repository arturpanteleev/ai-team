# Retention & GC (политика хранения)

Статус: идея
Источник: docs/audits/2026-08-05-technical-audit.md P2

## Задача

Политика хранения и уборка всего, что растёт: candidate worktrees, immutable
runs, CAS blobs, web sessions, логи. Сейчас ничего не удаляется никогда.

## Ценность для продукта

Каждый run оставляет worktree и полный evidence tree; на активном
использовании диск заканчивается незаметно — и пользователь винит продукт.
Уборка с явной политикой превращает «локальный инструмент» в «инструмент для
постоянной работы»: предсказуемый footprint диска, быстрый листинг ранов,
никаких тысяч мёртвых веток. Отдельно важен баланс с гарантиями: immutable
evidence нельзя удалять молча — политика должна быть явной и настраиваемой,
иначе подрывается доверие ко всей системе доказательств.

## Рекомендации по реализации

- `ai-team gc [--dry-run]`: candidate worktrees завершённых ранов; runs старше
  N дней/сверх M последних (с сохранением терминальных manifest'ов); CAS blobs
  без ссылок; истёкшие web sessions;
- конфиг: retention-секции с разумными дефолтами (например, 30 дней / 200
  ранов);
- удаление только через gc-команду, никогда — на горячем пути pipeline;
- dry-run сначала, удаление после подтверждения.

## Как проверить

1. После gc диск освобождается, последние N ранов и их отчёты доступны.
2. Активный ран (lock занят) не удаляется ни при каких флагах.
3. Dry-run показывает план удаления байтами, не удаляя ничего.
