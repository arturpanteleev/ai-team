# Review mesh (мультиагентное ревью)

Статус: idea
Источник: ALK parity — `docs/reference/review-mesh.md`, `review-verdict.md`

## Задача

Независимое ревью кандидата несколькими субагентами с разными ролями и
фокусами. Дефолт — один субагент (текущее поведение); панель включается
конфигом для ответственных задач.

## Ценность для продукта

Одно ревью одной моделью — это одна точка зрения и один набор слепых пятен.
Панель ревьюеров с разными фокусами (корректность, security, performance,
тесты) и, опционально, разными моделями находит то, что пропускает одиночка,
и снижает риск «сам себе одобрил». Кворум и синтез превращают набор мнений в
решаемое заключение, а не шум. Для продукта это главный рычаг качества без
изменения ядра: детерминированные проверки остаются прежними, растёт глубина
смыслового контроля. Для команд — настраиваемая строгость: тривиальные правки
ревьюятся одним, релизные — полной панелью.

## Рекомендации по реализации

- конфигурация панели: N ревьюеров, у каждого роль/фокус + опционально своя
  модель/хост;
- сборка пакетов: diff + артефакты + критерии роли каждому ревьюеру;
- импорт вердиктов/замечаний, синтез сводки, дедупликация повторов;
- классификация замечаний (обязательное/рекомендация/нерелевантно) и quorum
  при расхождении;
- дефолт лёгкий: 1 ревьюер = сегодняшнее поведение, mesh — opt-in;
- переиспользовать существующий verdict-контракт для каждого участника;
- разные модели — через adapters-layer / model-routing.

Ориентир: Review Mesh у ALK (packets → import → synthesize → quorum check).

## Как проверить

1. Дефолт не изменился: обычный run делает одно ревью.
2. Панель из 2–3 ревьюеров даёт синтезированную сводку замечаний без дублей;
   каждое замечание прослеживается до источника.
3. Расхождение вердиктов разрешается по quorum-правилу конфига; итог
   попадает в evidence как обычный verdict этапа.
