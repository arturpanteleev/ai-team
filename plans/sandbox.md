# Sandbox (OS-level containment)

Статус: idea
Источник: AUDIT.md C-01; ALK parity — `docs/reference/sandbox-boundaries.md`

## Задача

Запускать агента и проверки в замкнутой среде уровня ОС, а не с правами
текущего пользователя на host. Сейчас это честно задокументированное
ограничение: ai-team работает только на доверенном локальном проекте.

## Ценность для продукта

Что происходит сегодня, по-простому: когда ai-team запускает агента или
`go test`, они выполняются как ты — со всеми твоими правами. Значит код,
который выполняет агент (тесты, build-скрипты, зависимости проекта),
технически может прочитать `~/.ssh`, `.env`, API-ключи, сходить в сеть,
изменить файлы за пределами репозитория. Это не паранойя: prompt injection
через содержимое тикета или зловредная зависимость — реальные каналы.

Sandbox убирает этот класс рисков целиком и открывает сценарии, которые
сейчас запрещены самим README:

- **недоверенный вход**: задачи из тикетов с текстом чужих людей;
- **чужой код**: ревью/доработка сторонних репозиториев;
- **спокойный авторежим**: автономность перестаёт быть риском, потому что
  «вне песочницы» агент физически не выходит;
- **гигиена секретов**: ключи просто не видны процессу агента — их нечего
  утечь.

Для продукта это разница между «инструментом для себя» и «инструментом,
который можно дать команде/клиентам». ALK решает ту же границу через
раздельные receipts (filesystem / network / process / environment отдельно
от git write-scope) — это проверяемое утверждение о том, что происходило
внутри прогона.

## Рекомендации по реализации

Большая задача, меняет модель угроз — начинать с отдельного обсуждения
threat model и профилей trusted-local vs strict-sandbox. Направление:

- интерфейс `SandboxBackend` с явными capabilities;
- strict backend: Linux container/bwrap; эквивалент для macOS (VM/seatbelt);
- read-only source + отдельный writable candidate mount (candidate worktree
  уже есть);
- deny network по умолчанию + явные grants; минимальный env allowlist +
  отдельная передача credentials;
- CPU/memory/pid/disk/time limits;
- receipts по осям containment в evidence; strict profile fail-closed без
  sandbox.

## Как проверить

1. Hostile fixture внутри run не может прочитать файл вне разрешённых
   mount'ов, выйти в сеть или изменить live target.
2. Секреты (SSH/GH/env) отсутствуют в окружении процесса агента.
3. Timeout/cancel не оставляет процессов-потомков.
4. Strict profile без доступного backend отказывается запускаться.
