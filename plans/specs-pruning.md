# Specs pruning (62 → ~10 capability-спек)

Статус: идея
Источник: docs/audits/2026-07-25-scope-review.md шаг 10, раздел 6

## Задача

Сократить openspec/specs с 62 файлов до ~10 ключевых capability: control-
plane-safety, delivery-executor, run-evidence, deterministic-checks,
workflow (graph+gates), cli-interface, web read model, web security,
adapters. Удалить agent-* спеки (дублируют def.yaml+prompt.md — настоящий
источник истины), UI-мелочи, спеки-задачники; оставить одну копию opsx-
инструкций на инструмент (сейчас 15 файлов в 3 местах).

## Ценность для продукта

Спеки — это контракт, который мы обещаем поддерживать: 62 файла = либо
врём, либо тонем в синхронизации. Уже сейчас часть спек противоречит коду
после рефакторингов, а три копии opsx расходятся при правках. Узкий набор
живых спек = правдоподобное обещание «спека соответствует коду», быстрее
onboarding читателей, дешевле каждое изменение. Для внешних наблюдателей
короткая спецификация — лучший питч архитектуры, чем папка на 60 файлов.

## Рекомендации по реализации

- критерий оставления: спека описывает гарантию ядра, нарушение которой —
  баг; всё остальное (описания агентов, UI-детали, чеклисты) — удалить или
  перенести в docs/;
- слить workflow-graph/transitions/loopback/rollback в одну workflow-engine;
- opsx: оставить .claude + .opencode по одной копии каждой команды;
- прогнать make specs; проверить отсутствие битых ссылок.

## Как проверить

1. make specs зелёный на сокращённом наборе.
2. Grep не находит ссылок на удалённые спецификации.
3. Каждая оставшаяся спека проходит ручную сверку с кодом (чеклист).
