# Structured logging (уровневый логгер контроллера)

Статус: идея

## Задача

Заменить россыпь `fmt.Printf` в ядре на уровневый структурированный логгер
(debug/info/warn/error) с режимами `--quiet` и `--json` для машинного
потребления.

## Ценность для продукта

Консольный вывод сегодня — это UI и лог одновременно: его нельзя отключить,
отфильтровать или распарсить. Скрипты и CI не могут программно узнать исход
шага без regex по русским фразам. Структурированный лог даёт три поверхности
из одного источника: человек читает красивый вывод, скрипт парсит JSON,
evidence сохраняет события. Это ускоряет интеграции (тот же progress-bridge
и notifiers опираются на события, а не на текст), упрощает поддержку
пользователей («пришли вывод --json» вместо скриншотов) и убирает шум из
CI-логов.

## Рекомендации по реализации

- обёртка над log/slog: поля run_id/stage/attempt по умолчанию;
- человеко-режим остаётся дефолтом в TTY; --json для pipe/CI;
- запрет fmt.Printf в pkg/ вне ui-пакета (линтер);
- события уже типизированы (context-checkpoints) — логгер рендерит их же.

## Как проверить

1. `--json` вывод парсится как поток JSON-объектов со стабильными полями.
2. `--quiet` печатает только ошибки и финальный результат.
3. Линтер падает на новом fmt.Printf вне разрешённых мест.
