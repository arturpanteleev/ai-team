# Surface pruning (срезать дублирующие поверхности)

Статус: идея
Источник: docs/audits/2026-07-25-scope-review.md корзина 2

## Задача

Удалить поверхности, дублирующие веб-дашборд: `pkg/report` (HTML-генератор
~570 строк — фронт уже рендерит checks/mutations/delivery), консольный
прогресс/статус-бар `pkg/ui` (описан двумя спеками, ни одной не
соответствует). Console notifier оставить минимальным.

## Ценность для продукта

Две витрины одних данных = двойная стоимость каждого нового поля (написать
дважды, проверить дважды, задокументировать дважды) и гарантированное
расхождение. Одна витрина (веб) = один источник правды о состоянии, быстрее
развитие UI, −~800 строк поддержки. Консоль остаётся с честным минимумом:
этап начался/закончился, вердикт, где смотреть подробнее. Это задача
гигиены, освобождающая время для фич; делать только при уверенности, что
web-витрина закрывает сценарии (уже закрывает).

## Рекомендации по реализации

- удалить pkg/report + вызовы из pipeline; stage/final отчёты заменяются
  web detail page + events timeline;
- упростить pkg/ui до цветного вывода этапов без ANSI save/restore магии;
- обновить спеки report-* / observability;
- проверить, что immutable reports в run root больше не нужны либо
  остаются как артефакт без генератора (решить по факту).

## Как проверить

1. make verify зелёный; grep удалённых символов пуст.
2. Веб показывает всё, что показывал HTML-отчёт (чеклист сравнения).
3. Строки Go в пакете pipeline/web сокращаются на ~800.
