# Task templates (шаблоны workflow)

Статус: idea
Источник: ALK parity — `templates/tasks/`

## Задача

Готовые workflow-пресеты, запускаемые одной командой. Шаблон = граф + набор
агентов + чеки + approval-политики под тип задачи. Пользователь говорит
«это багфикс» и получает правильный конвейер, а не собирает конфиг вручную.

## Ценность для продукта

Порог входа падает с «настрой граф и роли» до «выбери тип задачи» — это то,
что делает продукт пригодным для чужих рук и для быстрых бытовых задач.
Шаблоны кодируют накопленный опыт удачных процессов (что проверять у
багфикса, что у release) и делают его воспроизводимым. Исследовательские
шаблоны открывают применение вне разработки кода: анализ и планирование как
первоклассные сценарии с теми же гарантиями. Для команд шаблоны = единый
стандарт процесса вместо «у каждого свой конфиг».

## Рекомендации по реализации

Набор из ALK (ориентир): bug fix; idea → PR; PR review; merge conflict
repair; release readiness.

Исследовательские (без кода, результат = артефакт, терминал после
архитектора):

- **spike** — «есть штука, нужно разобраться»: быстрое исследование →
  артефакт с планом решения. Граф: analyst → architect → done, один проход
  без ревью;
- **analytics** — глубже: исследование и обоснованное техническое решение с
  альтернативами и рисками → артефакт на ревью. Граф: analyst → architect →
  reviewer → done.

Отличие одной строкой: spike отвечает «как это сделать», analytics — «как
правильно и почему».

Реализация: пресет как встроенный конфиг v4 (граф уже умеет всё:
loopback-рёбра, approvals, max_visits); `ai-team run --template <name>`
либо выбор в вебе; пользовательские шаблоны в project/user слое рядом с
агентами.

## Как проверить

1. `--template bugfix` создаёт run с корректным графом без ручного конфига.
2. spike/analytics завершаются артефактом-планом/решением и не трогают git.
3. Пользовательский шаблон в project-слое переопределяет встроенный и виден
   в списке.
