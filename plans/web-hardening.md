# Web hardening (точечные закрытия)

Статус: идея

## Задача

Закрыть известные nit'ы web-слоя: lazy-only очистка истёкших sessions
(утечка памяти), `Secure` cookie флаг доверяет спуфябельному
`X-Forwarded-Proto`, `ReconcileInterrupted` обновляет все running rows без
scope по target/run.

## Ценность для продукта

Каждый пункт мал, но относится к поверхности, которой продукт обещает
безопасность (session/CSRF/projection): копейки здесь умножаются на доверие
ко всему security-нарративу. Утечка сессий — вопрос долгоживущих процессов
(обязательный cloud-режим); спуфабельный заголовок — классическая ловушка
при выставлении за прокси; нескоупed reconcile — риск чужих ранов при
мультитенантном использовании. Дешёвый пакет, закрывающий хвост перед тем,
как заявлять web control plane готовым.

## Рекомендации по реализации

- janitor goroutine / TTL-sweep для sessions; метрика активных сессий;
- Secure flag: конфиг `--trust-proxy <cidr>` вместо безусловного доверия
  заголовка;
- ReconcileInterrupted: WHERE scope по target (колонка уже есть) + только
  раны этого контроллера;
- обновить server_test негативными кейсами на каждый пункт.

## Как проверить

1. Истёкшие сессии исчезают из памяти без обращений (тест времени).
2. Запрос с поддельным X-Forwarded-Proto не получает Secure-cookie поведения
   вне доверенного прокси.
3. Чужой running row другого target не трогается reconcile-ом (тест).
