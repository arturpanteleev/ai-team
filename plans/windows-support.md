# Windows support (позиционирование и честность)

Статус: идея
Источник: AUDIT M-04

## Задача

Определиться с Windows: либо заявлять поддержку (CI windows runner, e2e,
починка flock-fallback/lock_other, path semantics), либо официально
зафиксировать ограничение «macOS/Linux only» в README, help и спеках.
Третьего (молчаливое «наверное работает») быть не должно.

## Ценность для продукта

Половина dev-рынка сидит на Windows: молчание = пользователи пробуют, ловят
неясные ошибки на lock'ах и путях, уходят с ощущением сырого продукта — плюс
тихие баги в кросс-платформенном коде, который никто не гоняет. Явная позиция
в обе стороны даёт ценность: либо новый сегмент аудитории с рабочей
поддержкой, либо честное ожидание и освобождение от класса багов
(документированное ограничение позволяет упрощать код). Даже выбор «не
поддерживаем» — это улучшение продукта.

## Рекомендации по реализации

- сначала решение по матрице: кто целевая аудитория, сколько стоит
  windows-runner CI;
- если поддерживаем: e2e job на windows-latest; починить lock fallback
  (сейчас no-op), path normalization suite, symlink-семантика;
- если нет: README/help/specs явно «requires macOS or Linux», валидация при
  старте на неподдерживаемой ОС с понятным сообщением.

## Как проверить

1. Заявленная платформа проходит полный e2e-сьют в CI.
2. Незаявленная платформа получает понятное сообщение при init/run, а не
   случайный падёж.
3. Документация нигде не обещает лишнего.
