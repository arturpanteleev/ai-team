# Workflow profiles (fast / standard / regulated)

Статус: idea
Источник: TECHNICAL_AUDIT «Роли и scope»; SCOPE_REVIEW

## Задача

Пресеты строгости workflow одним полем конфига: `fast` (минимум человеческих
решений), `standard` (текущий дефолт), `regulated` (полная панель approvals +
обязательные чеки). Профиль разворачивается в граф/approvals при init.

## Ценность для продукта

Текущий дефолт требует ~6 человеческих решений на фичу — для одного человека
это непомерно, и он либо бросает продукт, либо выключает гарантии целиком.
Профили возвращают замысел «простой цикл разработки» без отказа от строгого
режима: быстрый личный цикл, командный стандарт, регулируемый процесс — одна
и та же система, три уровня. Это прямой рычаг удержания пользователя: цена
входа падает до нуля без потери потолка строгости.

## Рекомендации по реализации

- поле `profile:` в config v4; компиляция = базовый граф + overrides профиля;
- fast: approvals только на delivery + rejected-рёбрах; standard: текущий
  дефолт; regulated: все рёбра + обязательные checks классов;
- `ai-team init --profile fast`; смена профиля — валидируемая операция;
- профили не отменяют ручной конфиг: явные edges сильнее профиля.

## Как проверить

1. fast-профиль доводит типовую фичу до PR с ≤1 человеческим решением.
2. regulated сохраняет полный approval-периметр (дифф политик виден).
3. Явный edge в конфиге переопределяет профиль; конфликт валидацией ловится.
